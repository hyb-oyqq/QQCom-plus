# QQCom 后续工作

这里只列未完成事项，不把界面占位或设计稿当作产品能力。当前实现见 [README](../README.md)。

## 优先级

| 优先级 | 工作 | 完成依据 |
| --- | --- | --- |
| 高 | 测量持续高负载，给 I/O 到 GUI 的消息批次设容量与背压策略 | 吞吐、事件延迟、内存、关闭排空可量化；丢弃必须可见 |
| 高 | 慢盘下后台日志、轮转与配额 | 顺序、落盘错误、磁盘满和退出排空测试通过 |
| 高 | 长历史分片重绘 | 切格式/过滤时仍响应输入，不改变已应用条件 |
| 中 | 统一发送队列与部分写入处理 | 按目标保存剩余 offset，TCP 多 peer 结果和 TX 计数有明确口径 |
| 中 | 真实 A/B 路由 | 保留原始字节、UDP 边界、peer 选择、去环和目标拥塞策略 |
| 中 | 网卡刷新与大指令表性能 | 保留当前选择，异步发现；根据实测决定是否改为 model/delegate |
| 后续 | 多工作区、完整抓包/回放、协议扩展 | 有明确需求后再拆控制器、解析器和存储格式 |

现有主输入框定时发送和指令批量发送已实现；独立周期任务管理器、任务恢复和调度队列仍未实现。路由编辑器只提供预览，目前不会桥接数据。

## OTA 与协议扩展

Windows OTA 第一版已经接入：客户端读取 Gitee 静态清单，下载 Release zip，校验大小和 SHA-256，再由独立 PowerShell 更新器等待主程序退出并直接覆盖发布目录。按当前需求不做旧版本回滚；失败时保留日志，用户可重新安装同一 Release。完整流程见 [OTA 方案](OTA.md)。

文件传输在发送区的「文件收发」标签中：RAW 用于无协议边界的字节流，YMODEM 用于带文件名、长度、CRC16、ACK/NAK、重传和双 EOT 的单文件传输。传输前后可以各发一条快捷指令，并进行中显示载荷 CRC。后续工作是实机验证不同 BLE/串口助手的 MTU、分包节奏和断链行为。
