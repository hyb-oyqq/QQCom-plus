# 2026-10-07 审查与整理归档

本文记录当时完成的工作和测量证据，不代替 [当前架构](../ARCHITECTURE.md) 或 [待办](../ROADMAP.md)。

## 审查结论与修复

固定 A/B 双端点适合现有模块化单体。一个 I/O 线程配合 Qt 异步通信足够，无需引入通用事件总线、插件注册器、每端点线程或额外控制器层。保留传输接口、纯组帧器和消息值对象。

| 问题 | 处理 |
| --- | --- |
| TCP 多客户端共享缓冲，尾帧丢失来源 | 每个 peer 独立组帧、来源和单次空闲定时器，离线输出尾部 |
| 空闲计时和结束符搜索 | 非空输入重新计时、空缓冲停止；只重查跨片段尾部，避免重复扫描全部历史 |
| 极小长度兜底遗漏 | 所有组帧模式拆帧后统一检查剩余缓冲阈值 |
| TCP 关闭遍历重入、无客户端写入误报 | 先移出连接容器并断开回调再关闭；无客户端明确拒绝写入 |
| 退出遗漏尾部和日志末批 | I/O shutdown 排空组帧，GUI 接收尾帧后写完日志待处理批次 |
| 指令文件格式双实现 | 统一使用 CommandFormats，QSaveFile 原子导出，补全错误与格式标签 |
| 历史模型单批超预算 | 统一裁剪并增量维护字节数，单批也受预算约束 |
| 界面混合职责和遗留成员 | 拆出 TrafficModel/TrafficFilter，复用字节格式化，删除未使用成员/空槽 |
| 端口显示与交互 | 网卡名称及完整 IPv4 不省略；波特率覆盖 2000000；当前组重命名；高级参数行合并 |
| 其他回归 | 性能 tooltip 接线、滚动取消跟随、端点错误来源、TCP 读缓冲上限 |

修改后仍存在入口队列无容量、GUI 同步写盘/重绘、部分写入和广播 TX 统计不完整等限制，没有宣称整个程序不存在缺陷。

## 性能证据

同机 Qt 6.10.1 / MSVC 2022 Release，结束符 CRLF、阈值 2 MiB，连续输入 64 字节无结束符片段，每场景 7 次取中位数并核对输出：

| 场景 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 64 KiB 分片累积 | 22.4565 ms | 0.1065 ms |
| 256 KiB 分片累积 | 322.448 ms | 0.3923 ms |
| 1 MiB 分片累积 | 5185.02 ms | 1.4251 ms |
| 一次输入 20,000 个完整帧 | 1.9118 ms | 1.8271 ms |

结果证明消除了无结束符大缓冲路径的重复搜索，不代表整体应用提速倍率。默认 300 字节阈值与该压力场景不同。实际监视面板单场景（1024 字节/条、20 条/批、100 批）平均周期 32.82 ms、扣除等待后的均值 6.57 ms、最长 36.27 ms，超过 100 ms 为 0/100；这不是网络吞吐或长期内存上限测试。

审查后核心测试 20 passed / 0 failed，UI 测试 100 passed / 0 failed，包含初始化/清理。随后完整网卡文本修复的定向 UI 检查 9 passed / 0 failed。未验证真实硬件串口。复现入口见 [性能测试](../../tests/PERFORMANCE_TEST.md)；本机原始结果在忽略跟踪的 `build/audit/`。
