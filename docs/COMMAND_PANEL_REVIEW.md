# 快捷指令面板检查与优化

2026-11-05 检查，2026-11-06 发布复审。范围为快捷指令表格、面板、分组管理器及发送调度，保留现有界面、配置格式和 CLI 行为。

## 已处理问题

| 问题 | 原有影响 | 修改 |
| --- | --- | --- |
| 控件与表格数据两份状态不同步 | 改内容、Hex、延时、勾选、结尾符后，复制、删除或拖动用旧数据重建，可能覆盖编辑结果 | 每次编辑只同步当前行；所有结构操作使用同一份最新数据，数据快照直接返回隐式共享值 |
| 结尾符显示顺序与取值顺序错位 | 显示 `+\r\n` 的选项实际可能存为 CR，用户看到的内容与发送字节不符 | 修正显示顺序，把实际值存入选项 data，去除另一套索引转换函数 |
| UI 层承担跨组数据修改 | 面板先写来源组再写目标组，业务规则与控件耦合 | 管理器在完整校验后一次提交两组，保留顺序、UUID、参数，并只通知一次 |
| 数据快照扫描整表控件树 | 每次编辑、切组和导出都重新采集所有行，勾选移动按钮也重复扫描 | 普通编辑读取一行；勾选数量增量维护；只在实际批量操作时枚举勾选行 |
| 编辑一个分组重新序列化所有分组 | 指令数量增加后，点击勾选框也被无关数据拖慢 | 序列化缓存按组失效，保持即时配置更新；撤销、重做、导入、加载正确失效；重复 UUID 旧配置不共用缓存 |
| 所有分组通知都重建当前表格 | 新建其他组或改名也销毁行控件，丢失选择、编辑器和发送标记 | 比较当前组身份与指令值，只有内容变化才重建；名称、备注直接更新 |
| 一次批量发送为每条指令创建定时回调 | 大批次预建大量任务，停止只是让旧回调空跑，累加 int 延时可能溢出 | 独立 `CommandSendScheduler`，整批一个可撤销定时器，64 位单调截止时间，隔离回调内停止/重启 |
| 结构变化后继续使用旧行号 | 切组、增删、排序后高亮或延迟拖动可能操作其他指令 | 结构变化先停批量发送；拖动、右键菜单、删除确认及重命名携带结构版本，旧动作失效 |
| 表格重算行高时重复同步几何 | 批量 resize 行高又触发多轮控件定位 | 量高期间挂起几何联动，结束后统一同步；保留控件延迟析构保护 |
| 行高信号参数误用 | 把 `sectionResized` 的旧高度当成结束行号，多遍历或遗漏后续行 | 按 Qt 信号的行号同步对应行，不把尺寸用作行号 |
| 多余接口与历史实现残留 | 存在未定义的 `selectedCommands`、无人使用的查询、自制布尔守卫和面板查找内部按钮 | 移除死接口，使用 Qt RAII 守卫，表格暴露明确的循环状态接口，压缩历史补丁说明 |

## 性能口径

Windows 11 x64，Qt 6.10.1 MSVC 2022，Release，Fusion 浅色样式，windows 平台。`command_panel_perf` 使用临时配置和真实组件，4 组各 500 条指令，在构建完成后交错执行修改前/后版本 3 轮，以下取中位数。

| 操作 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 连续 60 次勾选编辑，含同步配置序列化 | 445.9 ms | 90.0 ms |
| 读取 100 次指令数据快照 | 51.8 ms | 约 0.002 ms |
| 无关分组改名 5 次，含事件、布局和延迟析构 | 9679.1 ms | 24.6 ms |

微秒级快照值接近测量下限，仅说明已消除遍历，不代表磁盘写入或端到端交互延迟。勾选计时不主动处理事件循环或刷盘，改名计时包含事件处理；相同口径下比较，不推断真实串口吞吐或大型表格的首次加载速度。原始输出在 `build/commands-perf-after/command_panel_perf.txt`；探针用法见 `tests/PERFORMANCE_TEST.md`。

## 验证与边界

核心用例覆盖跨组移动原子性、无效修改无副作用、缓存失效/撤销/重做、重复 UUID 配置、单定时器及信号回调内重启。UI 用例覆盖编辑后复制/删除/拖动、切组后旧动作失效、保留编辑器与选择、勾选/选中移动和发送进度。原有发送测试改为真实 UDP 回环对账；行内控件计数限定到表格，避免误计底栏的循环复选框。

发布复审补齐底栏移动菜单的结构版本检查：打开菜单后切组，旧动作失效，并有 UI 回归用例覆盖。旧测试夹具也已修正：徽章用背景主要像素取色，避免采到文字；发送与回车发送改用真实 UDP 接收器对账；断开日志使用异步等待，与监视区 16 ms 攒批一致。

最终核心全套：88 通过，0 失败。UI 全套：158 通过，0 失败，无跳过，CLI 集成使用 1.2.0 程序。更新清单测试：21 通过。OTA 打包和更新器测试通过，真实程序回环验证完成下载、校验、覆盖、保留配置和重启。回环验证以本次构建模拟旧版本号，不等同于干净机器安装旧版本后的验收。

日志：`build/release-review-core-final.txt`、`build/release-review-ui-final.txt`、`build/release-review-update-tests.txt`、`build/release-review-ota-tests.txt`、`build/release-review-local-update.txt`。中间一次核心运行的固定候选端口不可用；随后单独、全套信号跟踪和普通全套均通过。未改变传输实现。

1.2.0 完整运行目录：`build/releases/1.2.0/QQCom`；发布包和清单：`build/releases/1.2.0/QQCom-1.2.0-win64.zip`、`manifest.json`。目录仅包含运行文件，附带 Qt、MSVC 运行库、CLI 入口与说明，不包含 obj/moc 中间产物。稳定版清单应在 Gitee 附件上传并验证后更新。

仍使用 QTableWidget 和常驻行控件，首次加载及真实结构变化仍随行数增长。当前没有做 QAbstractTableModel/委托虚拟化迁移；若实际需要频繁管理数千到数万条指令，应单独测量并规划此项。分组管理器仍为单工作区单例，未来多工作区需要实例化服务。配置序列化仍在 GUI 线程执行，缓存减少无关组的工作，未把单个超大分组的序列化改为异步。
