# QQCom 界面与使用约定

## 端口选择

主界面固定 A/B 两行端点，类型和常用参数直接展示，高级参数在当前行下方展开；监视区、发送区、快捷指令通过分隔条调整。快捷指令和主界面之间的分隔条可以往主界面一侧推，端口条和监视顶栏的内容宽度不挡住手柄。动作按钮表达当前操作：连接/断开、监听/停止、绑定/解绑。这些两字按钮和发送按钮在两个字中间留出空隙。「正在连接」和「等待中」不加。TCP 客户端还在拨号时，按钮文字改为「正在连接」，颜色保持未连接的蓝；再点一次取消。已打开的端口按钮为红。点了监听、连接或绑定却没打开时，失败原因用红色写在这一行下面，直到打开成功或改了参数；底部状态栏同时用红色短时提示。纯数据不把这条错误画进数据区。字段错误通过边框和悬停原因提示，状态及离散事件进入日志。A/B 桥接建立后，按钮同样变为红色，文字是「停止桥接」。桥接只由再点这个按钮关闭；端口断开、异常、改参数或设备暂时不可用都不关闭。

| 类型 | 常用配置 | 注意事项 |
| --- | --- | --- |
| 串口 | COM 名称及设备描述、波特率 | 数据位/校验/停止位/流控在高级设置；可输入自定义波特率 |
| TCP 客户端 | 对端 IPv4 或主机名、对端端口 | 异步连接，支持超时；拨号期间按钮显示「正在连接」。连上后数据区写一条带对端地址的「已打开」 |
| TCP 服务器 | 本地网卡、本地端口 | peer 身份保留到数据记录；监听成功不代表已有客户端。每个客户端握手完成后，数据区写「客户端 IP:端口 已连接」 |
| UDP | 本地网卡、本地端口、可选目标 IP/端口 | 本地地址用于接收，目标地址用于发送。首次收到某个来源的数据报时，数据区写「对端 IP:端口 已连接」 |

串口流控默认 `None`；`RTS/CTS` 启用硬件握手，`XON/XOFF` 启用软件流控。打开成功前显式释放 DTR；`None` 和 `XON/XOFF` 同时释放 RTS，`RTS/CTS` 的 RTS 由驱动控制。Windows 下同时清除驱动残留的 DSR 发送握手和接收门控，避免未接 DSR 时收发受阻。关闭时不恢复打开前的串口设置，避免重新置为有效的旧 DTR/RTS 状态影响设备复位或启动模式。这里的“释放”指逻辑未有效，USB 转串口芯片可能使用低电平有效信号；驱动在打开端口瞬间产生的引脚跳变仍需结合设备电路实测。

TCP 服务器/UDP 本地地址从网卡列表选择，保存 itemData 中的 IP，不解析显示文本。条目完整显示“网卡名称 · IPv4 地址”；选中项及下拉列表都不使用省略号，按内容和字体尺寸撑开。`0.0.0.0` 表示监听所有 IPv4 网卡，不是发送给对端的地址。

本地端口 `0` 表示由系统分配，绑定成功日志显示实际端口；需要让外部设备固定访问时使用明确端口。波特率和端口框按当前数字收紧，位数变多时再加宽，编辑区要放得下当前文字，并计入样式边框、箭头和 DPI。A/B 主字段左缘对齐。尾部框不再统一成一样宽。较短的名称在标签列里把字拉开，和「监听网卡」这类四字名称两端对齐。地址和当前波特率、端口都不能被裁掉来换窄布局。串口行和网络行同高，控件顶缘对齐。

串口后台约每 2 秒扫描，列表仅在快照变化时更新。拔出后保留原选项并提示不可用，不自动连接其他设备。主参数行上的「自动恢复」默认关闭，放在高级按钮前面；切到 TCP 服务器时隐藏。勾选后，异常断开会每 1 秒重试一次：串口先等一次新扫描，确认上次那个口还在才打开，避免用拔出前的旧列表空打；TCP 客户端和 UDP 按间隔重连。TCP 服务器不重试，客户端断开后监听保持，要由客户端再连。打开失败只再记一条等待说明，不每拍重复错误。点「等待中」取消本次恢复，勾选本身保留，下次启动仍记得。网卡列表在控件创建时枚举，运行期间不随网卡插拔刷新。

## 端口告警

未连接、正常运行和用户主动断开时，程序图标保持原色，A/B 徽章也保持各自身份色。端口行不额外放感叹号或告警弹出菜单；原因沿用底部状态栏和日志。未确认的端口故障使程序图标整体变为红色，底部对应状态点变红；警告或恢复后尚未查看时，程序图标整体变为黄色。变色保留图标的白色图案、明暗和透明轮廓。新告警每 500 ms 切换明暗，持续约 5 秒后常亮；窗口在后台时，Windows 任务栏按钮额外闪烁 3 次。自动恢复的「等待中」按钮在亮、暗主题下均为黄色，恢复成功或取消等待后按实际连接状态恢复按钮外观。

串口设备错误、打开失败和 TCP 客户端意外断开属于端口故障。自动恢复期间，未确认的故障保留红色告警，连接状态显示「等待恢复」；同一原因的重复失败只累计次数，不重启闪烁，也不重复写错误日志。单次发送/读取失败、数据丢弃、TCP 服务器客户端离开或拒绝超额连接属于黄色警告，不把仍在监听的服务器标成故障。没有客户端以及 UDP 暂时没数据均不产生告警。

窗口被激活，或用户在窗口内点击、按键时，将当前 A/B 提醒统一标为已查看，停止闪烁并恢复程序图标原色。前台发生异常时不会仅因「当前已激活」立刻确认，而是等下一次用户操作。确认不改变连接状态，不删日志，不清底部错误原因；没有自动恢复时端口仍为未连接，自动恢复中则继续显示黄色「等待中」。输入照常交给原控件；仅在有未确认提醒时临时监听输入，确认后立即移除，不增加定时器或通信线程处理。自动扫描、数据显示刷新、鼠标悬停及其他窗口的输入不确认提醒。对应端口的参数修改或连接/停止操作也保留该端确认能力。同一次故障的自动重试即使原因变化，也只更新记录、不重新点亮。用户手动重新连接后若再次失败，作为新故障重新提醒。重新打开并稳定约 2 秒后，故障才解除；未查看的故障留下黄色「已恢复」提示。主动断开、取消连接或取消自动恢复立即回到正常外观，在途的重试结果不再重新触发告警。A/B 独立记录，程序图标取两端未确认提醒的最高级别：红色优先于黄色。显示过滤不影响告警产生；本次运行各端保留最近 16 条合并记录。

## UDP 来源与发送

UDP 没有握手。绑定成功后可收数据；第一次收到某个来源的数据报时，数据区记「对端 IP:端口 已连接」。这只说明这个来源出现过，不会自动把该来源设为发送目标。

每个端点的来源列表保留本次打开后最先出现的 256 个来源，满额提示一次；其他来源的数据仍正常接收，记录保留实际来源地址，不再为其追加列表或首次出现提示。启用组帧时，每端最多保留 256 个尚有缓冲的来源；满额时先按流片段输出最久未活动来源的残留，再回收其会话和定时器，提示一次。这会提前结束旧来源的半帧，不丢弃字节，不合并不同来源。重新打开端点会重置来源列表和容量提示。

- 目标 IP 留空时只接收，发送不可用。需要回复时填写明确的目标 IP 和端口。
- 收发记录在方向后带上对端 `IP:端口`。接收用 `<<--` 标来源，发送用 `-->>` 标写出目标。串口没有对端，箭头仍然画出，后面不跟地址。状态、警告、错误不画箭头。TCP 服务器一次写给多个客户端时，日志无法归到某一个地址。前缀只用 ASCII：`RX`、`TX`、`TX+FWD`、`TX+MAN`、`TX+TIMER`、`TX+SAMPLE`、`I`、`W`、`E`、`S`。`I` 是信息，`W` 是警告，`E` 是错误，`S` 是状态。信息包括首次出现的 UDP 来源、接入的客户端，以及打开「提示日志」后的组帧说明。警告包括等待串口重新出现、按间隔重试。错误包括打开失败、断开和丢弃。状态包括端口打开、关闭，以及桥接建立、停止。屏幕上一行按内容拼接，顺序是时间、端口、方向、字节数、箭头、对端，中间不补空格。行号在左侧单独一列，不写进这一行。字节数只出现在 RX/TX；I、W、E、S 没有载荷，不标长度。关掉方向时，RX/TX 的字节数改放在时间和冒号之间。文件日志和导出仍是制表符分隔。
- 首次收到某个来源时，数据区写一条信息，前缀为 `I`：「对端 IP:端口 已连接」。同一来源不重复写。隐藏信息分类会隐藏这条日志。来源列表不是在线连接列表，也不改发送目标。
- 默认 UDP 本地端口为 `0`；跨机器测试需告知对端实际绑定地址/端口，并确保防火墙放行。

## 接收组帧

| 模式 | 输出时机 |
| --- | --- |
| 不拆分（默认） | 每次收到数据直接输出，不缓存 |
| 空闲超时 | 从最后一次非空数据到达起，连续无新数据达到设定时间后输出 |
| 结束符 | 找到完整结束符即输出，支持跨多次接收匹配 |

空闲默认 **10 ms**。例如 0 ms 收到 A，8 ms 收到 B，则应从 8 ms 重新计时，约 18 ms 后仍无新数据才输出 AB，不能从首字节开始算固定窗口。Qt 定时器在系统繁忙时可能晚触发。

所有缓存模式同时支持长度兜底，默认 **2048 字节**；结束符模式也会因空闲输出未完成片段。关闭端点、TCP peer 离线和正常退出程序时输出缓冲最后的数据，保留真实来源。强制终止进程不属于正常关闭流程。

结束符默认不包含在输出中。组帧提示默认关闭，开启后记录兜底原因。端口已打开时，改空闲超时、结束符或缓冲阈值不必断开，半包按改之前的规则先输出。结束符还没写完时这次改动不生效，并弹出原因。结束符在回车或离开输入框时提交一次，不是边打字边生效：每敲一个字符就换一次规则会在中途把接收缓冲反复冲刷成流片段。TCP 服务器按 peer 分别缓存和计时，不把不同客户端拼成一帧。UDP 未启用组帧时保留原始数据报边界（含零长数据报）；启用后同样按用户规则拆分或跨数据报拼接，按来源 IP＋端口分别缓存和计时，绝不混合不同来源。启用组帧时零长数据报不提供字节，不产生帧也不延后空闲计时。组帧不负责修复 UDP 丢包或乱序。桥接转发与文件传输仍使用原始输入，不受接收组帧规则影响。

## 过滤与显示

首次启动时，监视区显示格式默认 UTF-8，手动发送格式默认 HEX；已有用户保存的格式优先恢复。

端点和 RX/TX/转发/信息/警告/错误/状态按结构字段筛选。关键词、排除词用英文逗号分隔，去掉首尾空白；多关键词任一命中即满足，多排除词任一命中即拒绝。支持大小写开关，当前为字面子串匹配，不支持正则表达式。

数据区顶栏从左到右是编码、过滤、A/B、RX/TX/转发、前缀、颜色、HEX、换行，右侧是设置、导出、滚动、清空、扩展。顶栏这四个显示开关用短名；「设置」菜单里写成「显示前缀」「显示颜色」「始终显示HEX」「自动换行」。程序初次启动时扩展区收起；之后用户展开或收起的选择会被记住，下次按上次的状态打开。扩展区收起后，它和数据区之间的左右拖动条隐藏，并且不再占宽度；数据区左右离窗口边的距离保持一致。展开后拖动条回到原位。A/B 使能时为黄，未使能时为灰。端口配置行前面的 A、B 徽章不跟这个黄：A 为琥珀色，B 为青色。数据区左侧始终有一列浅灰色行号。端口用行号右侧的短色标区分：A 为琥珀色，B 为青色；不属于某一端的行没有色标。悬停行号显示端口和名称。同一行里先后出现两个端口时，并排两根色标。复制和导出不带这列行号。勾选「显示前缀」后每条记录另起一行，并显示端口、收发方向、前缀时间戳和前缀数据长度。关掉后只连续显示接收到的数据，新数据接在上一包后面，换行只来自数据里的换行符；发送、信息、警告、错误和状态不显示，正文保持数据自己的颜色。菜单里的前缀时间戳、前缀数据长度和「始终显示HEX」变灰。「显示颜色」勾上时，UTF-8、GBK、ASCII 里的颜色标识按颜色显示，标识本身不出现；只取消加粗不会把颜色清掉。串口把一条转义切在两包里时，半截先留着，下一包接上后再着色，不把 `[36;` 画进正文。已经画出来的正文不等尾包；尾包一直不来时，半截过一小段时间后按原文补进正文。关掉「显示颜色」后，颜色前后缀按原文显示，正文不再上色。HEX 对照是这条记录的原始字节，不跟着屏幕上的替换字符和续接记号变。着色时藏起来的转义仍留在对照里。显示格式是 HEX 时列出收到的全部字节，颜色前后缀的字节也在其中。颜色开关不跟「显示前缀」走。端口方向没有单独开关，跟着「显示前缀」。「始终显示HEX」只在显示前缀打开时可用，在数据行之后另起一行显示 HEX 对照；显示格式已经是 HEX 时自动省略。「自动换行」按窗口宽度折行。「滚动」勾选时始终跟到最新记录；向上翻阅自动取消，拖回或滚回底部再自动打开。没有保存过偏好时，「设置」里的显示前缀、显示颜色、前缀时间戳、前缀数据长度、自动换行、显示信息、显示警告、显示错误、显示状态勾上，左侧行号始终显示，始终显示HEX关闭，「滚动」打开，「扩展」关闭。之后按上次保存的勾选打开。

数据区顶栏的「转发」开关只决定桥接产生的发送行是否出现在数据区。纯数据时这些发送本来就不显示，此开关要等打开「显示前缀」后才看得出。关掉后转发仍按原样进行，手动发送和接收不受影响。建立桥接和停止桥接各写一条状态，前缀为 `S`，正文写明方向和两端端口。这条状态不属于 A 或 B，A、B 只要有一端还在显示就留下；两端都关掉时一起隐藏。隐藏状态分类也会隐藏它。

底部状态栏在 TX 之后统计丢弃字节。没有丢弃时这一项隐藏；出现后用红色显示累计值，直到本次运行结束。读出失败、写出被拒绝、部分写出没写上的字节，以及建立桥接时丢掉的未读输入，都计入这里。数据区同时写一条错误，勾选记录时同一条进入日志。打开失败等没有载荷的错误不增加这个数。底部红色提示用短句，悬停仍是全文。打开端口后，已经到达的数据照常显示；只有建立桥接时才丢掉当时还没读走的输入。

底部状态栏右侧，「检查更新」、外观和窗口置顶各占一块浅底，中间留出与端点状态相同的间隔。外观菜单有「亮色」「暗色」「跟随系统」三项，当前项勾上，选择会记住，下次按上次打开。没选过时跟随系统。正常启动约 3 秒后自动检查更新；环境变量 `QQCOM_DISABLE_UPDATE=1` 只关闭这次自动检查，手动按钮仍然可用。快照和延迟探针不检查。

搜索候选包含对端、端点名、状态说明、详情、当前编码文本、UTF-8 及两种 HEX 写法。关键词和排除词改变后立即作用于后续数据；已有历史要等点击「应用过滤」才按这两个框重新筛选。「清除过滤」停用关键词过滤，方向和事件开关全部勾回，已输入的词保留。纯数据时仍只显示接收。

历史正在重建时，修改过滤条件（包括关键词、排除词和大小写）或显示设置会立即取消旧任务，按最新条件重新开始；不等待旧任务完成。相同条件重复点击不重新清空；任务完成后，若条件、格式、显示设置和主题不变，且后续记录仍按同一快照处理，再次应用直接复用结果。临时改条件期间收到过数据，即使后来改回原条件，也会保留待应用提示并重新过滤，避免漏补或多留记录。重建期间收到的数据也统一按本轮条件显示。按钮显示「重建中…」，底部显示「正在重建历史…」；清空取消当前重建。

A、B、RX，以及打开「显示前缀」时的 TX、转发、信息、警告、错误、状态，一点就作用到已经收到的行，不用再点「应用过滤」。纯数据时 TX、转发不改变屏幕；信息、警告、错误、状态四项取消勾选并置灰，内部记住原选择，重新打开前缀时恢复（包括重启后）。纯数据期间收到的事件仍进入缓冲和日志文件；例如 TCP 客户端被服务器断开会记录一条带原因的 E 错误行，打开前缀并显示错误即可查看，不重复追加 S 关闭行。「清除过滤」在纯数据下也保持四项不可选，打开前缀后四项全部恢复勾选。改前缀、颜色、HEX、换行或编码时，历史仍按上次已应用的关键词和排除词重绘。若关键词只在某种编码文本中存在，切换编码后命中结果可能变化，这是同一条件重新求值的结果。

时间、端口、对端、长度、HEX、换行、前缀及滚动跟随由「设置」菜单和顶栏同名开关控制。离开底部就取消跟随，回到底部再打开。缓冲释放必须提示；模型已释放的数据无法在下一次历史重绘时恢复。

## 发送与指令

发送区分为「手动发送」「发送文件」「接收文件」三个标签。手动发送前先校验编码、生成最终字节预览，再投递选中的 A/B 目标；定时发送按设定间隔发送主输入框内容。「发送」按住时底色明显更深，松开恢复；悬停只略深一档，不能代替按下。按下「回车发送」后，回车与「发送」按钮走同一条路，Alt+回车换行。旁边的「回车清空」默认关闭，只有回车发送成功才清空输入框；点「发送」和「定时」不清空。「定时」、间隔、「回车发送」、「回车清空」在同一行。间隔框按当前数字收窄，位数变多时再加宽。手动输入框的正文在下次启动时原样恢复，清空后也保持空白。发送成功表示本机接受写入，不是对端确认。

文件收发在「发送文件」「接收文件」标签中分别选择端点与协议：

- `RAW` 不传文件边界。发送选择文件；每块等本地写入接受后才计入进度和 CRC，再按所设间隔提交下一块。端点拒绝或部分接受时立即停止并报错，避免把未写出的字节计为完成；慢速串口可增大发送间隔。本地完成仍不代表驱动已全部发出或对端收到，需由对端校验。接收选择保存路径，点击「停止」提交接收结果。
- `XMODEM` 固定 128 字节块，不传文件名或长度，收发都选本地文件。接收端先发 `C`（0x43）请求 CRC16，约 3 秒没有数据改发 `NAK`（0x15）；也接受直接到达的经典校验和帧。发送端按 `C`/`NAK` 选择 CRC/校验和。末包用 0x1A 补齐，接收文件保留这些填充字节，不支持 1024 字节块。
- `YMODEM` 传递文件名与长度，发送选择文件和 128/1024 字节分包，接收选择目录。协议使用 `C` 启动、SOH/STX 分包、ACK/NAK、双 EOT 和空文件头结束，接收时清理文件名中的路径和 Windows 保留字符。

单文件上限 100 MB。XMODEM/YMODEM 使用临时文件提交，失败不留下未完成目标文件；不支持多文件批量传输。前置指令和后置指令在页内填写，各自可设置等待时间，等待期间的字节不进入文件或协议控制流。进行中显示速度、字节进度、重试、CRC 错误，以及文件载荷的 CRC16 与 CRC32。文件协议使用运行时原始字节，不受监视区组帧、结束符或空闲超时设置影响；两端需连接到同一条传输链路。

快捷指令支持分组增删和**重命名当前分组**，每条指令的说明仍在行内编辑。支持勾选、拖动排序、单条发送、按各行延时批量顺序发送。底部「移动勾选到」按勾选框移动指令；右键「移动选中到」按高亮行移动，Ctrl/Shift 可多选。右键已选行保留多选范围，右键未选行只操作该行。目标菜单列出其他分组，指令按原列表顺序追加到目标组末尾，保留全部参数和勾选状态并即时保存，移动后仍停留在来源组；正在进行的批量发送会停止。没有勾选或没有其他分组时，底部移动按钮不可用。按钮左侧的「循环发送」勾上后，同一批勾选指令发完最后一条回到第一条，按钮变为「停止循环」，再点一次停止。分组栏有「换行」，默认关闭。关闭时发送框单行，过长内容末尾省略，悬停可见全文。打开后按列宽折行，没有空格的指令也折，行高跟着变高；这个选择下次启动保留。编辑时长按回车仍提交，Shift+回车才插入换行。组列表没有独立的周期任务管理器。导入/导出支持 QQCom JSON、JCom `.port`、BLE `.blemsg`；外部格式不支持的字段不能保证无损往返。

## 日志与导出

文本记录按会话创建带时间戳的新文件，启动记录、清空会话和手动重新开启记录均遵循新建语义。未手动指定目录时写到程序目录下的 `log` 文件夹，默认基名 `QQCom-log`。「设置」菜单中的「打开当前日志」用系统默认程序打开正在写入的那一份，未记录时不可点；「日志位置」可改目录，「恢复默认位置」回到该文件夹。文件头含产品名、时间和编码，记录期间切换编码会插入格式变更标记；正常关闭写完待记录批次。

TSV 导出是当前历史模型的预览，不是完整原始抓包；超过单条预览上限的数据带有截断信息。文件日志与显示过滤独立，但记录内容仍按当前实现的预览/编码路径生成。当前没有文件轮转、磁盘配额、后台写盘或完整抓包回放。
