# 验收与性能计划

状态：待实现后的测试计划。下列测试未执行，性能数值均为初始目标；本次交付仅验证规划文档、源码定位及 Git 基线。

## 1. 测试分层

| 层次 | 工具与对象 | 主要目的 |
| --- | --- | --- |
| 核心单元 | Qt Test、FakeTransport、可控单调时钟 | 短写、队列额度、路由语义、编码与定时任务 |
| 网络集成 | Qt Test + 本机 TCP/UDP 对端 | 真实事件循环、连接、peer、数据边界和关闭 |
| 串口集成 | 已安装的虚拟串口对＋真实 USB 串口/设备 | 参数、吞吐、硬件流控、拔插和驱动错误 |
| 界面 | Qt Test 关键交互＋人工检查 | 类型切换、目标选择、暂停显示、停止操作、缩放 |
| 性能与长稳 | 独立流量生成器、进程指标、内部指标导出 | 吞吐、延迟、预算、界面响应和泄漏趋势 |

测试核心不得需要创建 MainWindow；时序测试优先注入时钟，不靠长 sleep。串口硬件不可用时标记跳过原因，不能将 TCP 回环通过当作串口通过。

## 2. 需求追踪与功能矩阵

| 测试 ID | 对应需求 | 场景 | 通过标准 |
| --- | --- | --- | --- |
| T01 | R01–R05 | 四类型及每类两个实例同时打开 | 各配置和计数独立，无跨线程 QObject 警告 |
| T02 | R02 | 波特率/数据位/校验/停止位/流控与占用/拔插 | 成功参数与设备一致，失败有原因，手动关闭不重连 |
| T03 | R03 | 成功、拒绝、超时、DNS 失败、连接中取消 | 状态准确，取消后不迟到变 Connected |
| T04 | R04 | TCP Server 监听无 peer、三 peer、指定/全部发送 | 无目标明确失败，数据只到指定目标，来源身份准确 |
| T05 | R05 | 两 UDP 来源交错发送、固定目的、零长/超长报文 | 来源不串、零长保留、超长拒绝且不截断 |
| T06 | R06 | HEX/文本切换、拆开的 UTF-8、含 NUL/非法字节 | 原始字节不变，展示有明确编码/边界标记 |
| T07 | R06、R08 | 高速接收时暂停/筛选/清空/隐藏监视 | 转发不变，缓存不越限，遗漏预览有计数 |
| T08 | R07 | 串口↔TCP Server、TCP Client↔串口 | 两方向逐字节一致，开启双向不产生内部重复转发 |
| T09 | R07 | 串口/TCP Client/TCP Server/UDP 的不同实例组合 | 覆盖 4×4 共 16 种有向类型组合，同类型使用两个实例 |
| T10 | R07 | TCP 多来源→串口，固定来源和全来源模式 | 默认单来源隔离；全来源行为与声明一致，不虚构响应归属 |
| T11 | R05、R07 | UDP↔UDP、流→UDP、UDP→流 | 报文数/长度/顺序符合所选分包契约 |
| T12 | R07、R08 | 慢目标、广播慢 peer、有限硬件流控 | 背压或隔离策略触发，积压有界，无静默损坏 TCP 流 |
| T13 | R08 | 模拟 write 返回部分、0、-1、bytesWritten 分段 | 未接受尾部正确续写，无重复/漏字节，完成计数准确 |
| T14 | R08 | 旧 generation 事件、断线重连、端口替换/删除 | 旧请求不写入新会话，结果可结算，worker 释放正确 |
| T15 | R09 | 编码、尾部、目标、单次/周期/列表发送 | 最终 bytes 与预览相同，断线停任务、定时不积欠爆发 |
| T16 | R10 | 保存/恢复、损坏/过大/未知版本、失效 peer 引用 | 仅合法快照生效，不覆盖坏文件，重启不自动发送 |
| T17 | R11 | 原始记录、轮转、无权限、磁盘满、记录队列满 | 可解码回原数据，失败标不完整，转发继续且内存有界 |
| T18 | R01、R06 | 连续切换类型 100 次，打开关闭 100 次 | 一次 RX 一次处理，无重复连接、资源持续增长 |
| T19 | R07 | 重叠规则、外部回显、运行中停用规则 | 内部一次投递；外部回显作为新 RX，停止/限流可控制 |
| T20 | R08 | 满载时停止发送、停止路由、退出程序 | 控制通道可用，正常退出按期限结算，不用 terminate |

T09 按源→目标矩阵逐格执行，UDP 涉及的转换按 T11 验证。每格至少包含二进制 00–FF、随机分块、单字节、高位数据及连续多次发送；收到的有效字节以长度、序号和 SHA-256 对照。TCP/串口按拼接后的流比较，不要求与 write/read 调用分块相同。

## 3. 关键边界测试数据

| 输入/操作 | 期望 |
| --- | --- |
| HEX `00 7F 80 FF` / `007F80FF` | `00 7F 80 FF` |
| HEX `0x01 0xA0` | `01 A0` |
| HEX `A`、`01 GG`、`0x1`、`01,02` | 严格报错，不过滤后发送 |
| 转义 `A\r\n\0\xFF` | `41 0D 0A 00 FF` |
| 转义 `\xF`、`\q`、末尾单独反斜线 | 报错，附位置 |
| 文本 `中`，UTF-8 | `E4 B8 AD` |
| 文本 `中`，Latin-1 | 不可编码，拒绝发送 |
| HEX `41` + CRLF 尾部 | `41 0D 0A` |
| UTF-8 被拆为 `E4 B8` 和 `AD` 两次流接收 | 相同 session/peer 的增量解码显示“中” |
| 两个 peer 的 UTF-8 残片交错 | 不跨 peer 拼接字符 |
| UDP 长度 0、1、1200、65507、65508 | 支持空包；按配置上限准入；65508 拒绝 |
| 分隔符跨两个 TCP 片段、超长无分隔符 | 分包正确；超长按错误策略停止，无无限尾部 |
| bytesWritten 为 2、1、3，原始请求 6 字节 | 总完成为 6，各阶段不重复记账 |
| 客户端 A 离开、B 获得相同列表位置 | 原 A 的请求失败，不能发给 B |

FakeTransport 还要覆盖“入队后关闭”“部分 Qt 接受后错误”“广播一成功一失败”“零写后没有立即 bytesWritten”“队列容量刚好等于限制”和“零长度报文冲击条目上限”。短写模拟是硬性测试，不能只用通常返回完整长度的本机 socket 替代。

## 4. 性能初始目标

统一采用 Release、Windows 10/11 x64、Qt 6.10.1、MSVC 2022。记录实际 CPU/内存/驱动、payload 大小、并发数和构建 commit；目标待首轮基准校准。

| 项目 | 初始目标 | 测量条件 |
| --- | --- | --- |
| TCP→TCP 大块吞吐 | 单向持续至少 20 MiB/s，运行 10 分钟 | 本机回环，64 KiB 输入块，接收端持续消费，原始记录关闭 |
| 显示开销 | 开启监视后，转发吞吐不低于关闭显示时的 90% | 同一机器、同一流量，显示允许有明确预览遗漏 |
| 小块转发 | 256 B × 10000 次/秒，至少 5 分钟无错误 | TCP 拼接后校验，不按 readyRead 次数统计包数 |
| 非拥塞转发延迟 | I/O RX→目标 Qt 接受，p95 ≤ 10 ms、p99 ≤ 25 ms | 1 MiB/s、1 KiB 数据块，单目标；不含线路/远端处理时间 |
| 可见延迟 | RX→模型可见 p95 ≤ 100 ms | ≤ 200 KiB/s，全部预览能被消费；满载时改验遗漏提示 |
| 停止响应 | 停发/停路由命令 p95 ≤ 100 ms | 数据入口满载，测 GUI 点击到 I/O 停止准入 |
| 串口 | 115200、921600 及设备支持的最高速率稳定转发 | 8N1 理论上限约 baud/10 B/s，实际目标取设备直连基线的 90% |
| 长稳 | 2 小时持续运行，无单调内存增长、无资源泄漏 | 4 端口、持续 5 MiB/s TCP＋可用串口流量，预热 10 分钟 |
| 内存 | 默认验收负载私有内存目标 ≤ 384 MiB | 同时记录各内部预算、队列项数；不同机器报告基线差异 |

任何“目标未达成”都要保留实际值和瓶颈分析，不以降低流量而不说明的方式判定通过。端到端延迟可另外由测试对端测量，与应用内部排队延迟分开报告。

## 5. 过载实验与结果判据

实验 A：TCP 源以 10 MiB/s 向 115200 串口转发。应很快产生背压，源 TCP 写入速度最终下降；队列不能无限增长。若串口/设备不支持可靠流控，明确记录不能保证设备侧 RX 无损的边界。

实验 B：串口/UDP 源持续输入，目标停止消费。不可背压策略应暂停规则并显示缺口，或在用户明确选择尽力模式时丢弃整片段/整报文并计数；不能静默继续一个被破坏的“可靠”会话。

实验 C：TCP Server 广播给一个快客户端和一个不读取客户端。分别验证“全部目标背压”和“隔离慢客户端”；后一模式中快客户端仍收到完整流，慢客户端被断开且失败可见。

实验 D：阻塞 GUI 消费 5 秒及让记录 worker 停止消费。检查 Qt 事件队列没有逐包无界积压；监视缺口与记录不完整独立上报，转发仍按规则执行。测试阻塞仅存在于测试驱动。

实验 E：每秒持续产生零长/1 B UDP 数据报。验证条目数上限、CPU 公平预算和停止按钮，证明“按字节有界”没有遗漏元数据增长。

## 6. 记录与发布门槛

每项测试记录：日期、commit、Kit、系统/硬件、拓扑、流量、配置、预期、实际、通过/失败/跳过、日志或测量文件位置。性能报告至少包含吞吐、延迟 p50/p95/p99、CPU、私有内存、队列峰值、RX/TX/路由丢弃/预览遗漏/记录缺口。

v0.1 发布前必须完成 T01–T20，硬件相关跳过项单独列入发布限制并安排补验；存在静默数据损坏、跨 peer 错发、无界缓存或无法停止的缺陷时不能视为首版完成。打包用匹配 Kit 的 windeployqt，在没有开发环境的 Windows 机器验证启动及四类通信依赖。
