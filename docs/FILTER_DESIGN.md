# 监视区过滤功能设计

状态：**F1 已实现**（代码与测试均已落地）。日期：2026-10-04，末次修订 2026-10-06。前置阅读：`PLAN.md` R06、`docs/UI_DESIGN.md` §4/§9.2、`docs/ARCHITECTURE.md` 监视区章节。

修订沿革：

- r2：过滤条形态由"顶栏按钮 + 折叠多行面板"改为**单行常驻条**（§7.1、§10 决策 5）。
- r3：形态定为**两行头 + 可折叠单行过滤条**（用户钦定：固定两行、按钮折叠、全部按钮带 Material 字形）；同时把设计稿从"草图"对齐到实际落地的类与 API（§3.2/§3.3）。
- **r4**：①**加上"对当前内容生效过滤"的按钮**——方案 B 的显式回溯提前进 F1，落地为 `重新过滤`（r5 更名为 `应用过滤`，§5）；②**去掉关键词 chip 与输入框的清除按钮**，多个条件改用**逗号**分隔（§4、§7.2）；③**`更多` 下拉去掉**，匹配选项直接摆成条上的按钮（§7.2）。三条的共同方向是**减少"同一件事的第二种表达"**：没有第二份条件视图、没有第二个入口。

- **r5（本次）**：①**显示设置必须立刻作用于已经收到的数据**（用户："看起是新数据才生效，这不符合要求"）；②**过滤要能"为当前所有已到达的数据"一次应用**（用户给的形态就是一个按钮）；③**HEX 对照行改用浅色**（它是附注而非数据本身）。
  支撑 r5 的是一次实测：**不在 `beginEditBlock` 里的每次 `insertText` 有约 100 µs 的固定开销**，而插入本身只要 1~2 µs；包进编辑块后**投影成本从 360 µs/行降到 6.9 µs/行（约 55 倍）**。"重投影全部历史"因此在成本上从"不可行"变成"点一下就有"。r5 据此把监视区从"只写日志台"改成**模型缓冲的投影**（§5、§6）。

- **r6（本次）**：**撤回"用缓冲预算换响应时间"的取舍**。用户拿 easyDebug 与 JCom 做了同一份压测：JCom 把整场数据原样留着，easyDebug 拖到最前面已经丢了最早的数据——换算下来正是"缓冲预算 ÷ 每条报文渲染出的行数"，也就是 16 MiB / 100 万块这种**隐形历史长度**在起作用。决定：**上限不再是历史策略，只做内存安全阀**（模型 512 MiB / 2000 万条，文本 400 万块 / 5.12 亿字符），正常压测碰不到；**安全阀触发时状态栏追加 `· 缓冲区已满`**（只说这一句事实，不再摊开两串对不上号的条数/行数；**不往日志里插标记行**），无声丢数据是唯一不可接受的行为。同时定下**日志记录的生命周期**（见 §10 决策 4）：程序启动 / 清除视图 / 手动开启三处都**新建带时间戳的文件**，绝不覆盖或追加。代价明码标出：跑到安全阀附近的会话，一次重投影会是秒级。

- **r7（本次）**：**顶栏开关重新排布**——顶栏常驻的是**方向开关（RX/TX）+ 显示开关（纯数据模式 / 同时显示 HEX / 自动换行）**；**事件开关（状态/警告/错误）让位回到显示设置菜单**（用户钦定，见 §10 决策 6）。三条理由：①这三个显示项是"随手切一下"的高频外观操作，藏进菜单要多两次点击；②事件开关与菜单里那批"显示哪些行类型"的选项同类，放一起更顺；③顶栏第一行的宽度是硬成本，宁可加宽窗口也不压缩按钮（用户钦定，见 §7.3）。实现上顶栏三个新按钮是显示设置菜单同名 `QAction` 的**门面**（`ViewToggles`）：状态唯一真源仍是 `QAction`，两处永远一致。

## 1. 目标与非目标

**目标**：让用户在 34 万行的实时流里快速聚焦到自己关心的那部分——按内容、方向、端点、事件类型、长度、对端、帧类型收窄显示，条件可组合、可排除、可持久化。

**非目标**：

- 不改通信行为。过滤只作用于**显示**，不影响收发、转发、记录、统计（沿用 R06 与 UI_DESIGN §4 的既有约定）。
- 不做服务端式规则引擎、不做跨会话的历史检索（属于未来的记录检索功能）。
- 不引入对全量文档的逐行扫描——这是与"数据性能优先"直接冲突的做法（见 §6）。

## 2. 现状与约束

现状（`TrafficPanel` + `TrafficFilter`）：

| 能力           | 现状                                         |   | 问题                 |
| ------------ | ------------------------------------------ | - | ------------------ |
| 搜索框          | 单个关键词，匹配当前格式渲染文本 / UTF-8 / HEX 两种写法 / 对端地址 |   | 只能 1 个词，无法排除，无组合   |
| 端点 / 方向 / 事件 | A、B、RX、TX、错误日志 5 个开关                       |   | 只有布尔维度，没有长度、对端、帧类型 |
| 生效时机         | 到达时判定（控制台语义）→ **r5 改为投影模型**（§5）              |   | 改条件后旧行仍在，看不到"过滤结果" |
| 计数           | 只有会话累计条数                                   |   | 看不到"被过滤掉多少"        |

三条硬约束（r5 修订后）：

1. **性能按两条路径分开算账**。**增量路径**（消息到达）成本恒定、与缓冲规模无关：判定短路 + 预编译，渲染走 `appendMessages` 的编辑块批写，实测约 6 µs/条。**全量路径**（重投影）与缓冲条数线性、实测 6.9 µs/条，所以"缓冲预算"就是"重投影预算"（§6）。
2. **视图是投影**：同一批记录可以按不同编码格式 + 显示开关反复重画。**外观（每行长什么样）改了就立刻重画已收到的内容**；**过滤条件（哪些行进来）只作用于新行，由「应用过滤」把它们补到已有记录上**。行号是会话内绝对计数，重投影后按结果从 1 连续重排。
3. **缓冲即能力边界（r6 重定）**：模型缓冲同时是"屏幕上能重画的历史"上限——**能回溯多远，取决于缓冲留了多久**。r5 把这个边界定得偏小（5 万条 / 16 MiB），实测压测一万多条就开始丢最早的记录；r6 改成**只做内存安全阀**（512 MiB / 2000 万条），并把"释放了多少"写进状态栏。这条边界依然存在，只是从"日常就会碰到"变成"机器快撑不住时才碰到"。

## 3. 过滤模型

### 3.1 条件（Rule）

全部条件作用在 `Traffic::Message` 的**结构化字段**上，不解析显示文本（与现有 `TrafficFilter::accepts` 同源）。

| 维度   | 取值                        | 说明                             |
| ---- | ------------------------- | ------------------------------ |
| 方向   | RX / TX / 状态 / 警告 / 错误    | 多选，命中任一即通过                     |
| 端点   | A / B                     | 复用监视区既有的 A/B 开关，不重复设条件         |
| 事件类型 | 状态迁移 / 警告 / 错误            | 与"显示错误日志"开关同源                  |
| 长度   | min..max 字节               | 用 `displayBytes()`（真实长度，非预览长度） |
| 对端   | 子串匹配 `source.peerAddress` | TCP 服务器/UDP 才有值                |
| 帧类型  | 流片段 / 数据报 / 完整帧           | `Framing` 枚举，排障时"只看完整帧"很常用     |
| 来源   | 自动 / 手动 / 定时 / 转发 / 示例    | 可选，用于排除自己发出的内容                 |

### 3.2 组合（`Options`）

落到代码上只有**一份条件快照**，没有 `FilterRule` / `FilterSpec` 这类中间层——F1 的条件维度全是布尔或词表，套一层规则对象只会多一次遍历而没有任何表达力收益（`FilterRule` 留给 F2 的长度/对端/帧类型，那时才真的需要"字段名 + 值 + 启用位"）：

```cpp
struct Options {                    // 一份条件快照，由条件条收集、由 Matcher 消费
    QSet<QUuid> endpoints;          // 端点；空集 = 该死，什么都不过
    bool rx = true;                 // 方向：RX / TX
    bool tx = true;
    bool states = true;             // 事件类型：状态迁移（端口打开/关闭/重连）
    bool warnings = true;           // 警告日志
    bool errors = true;             // 错误日志
    QStringList keywords;           // 内容：任一命中即通过（组内 OR，空 = 不过滤内容）
    QStringList excludes;           // 内容：命中任一即隐藏（黑名单）
    bool caseSensitive = false;
    bool regex = false;             // keywords / excludes 按正则解释
};
```

语义（一条记录按顺序判定）：

```text
端点命中 AND 方向命中 AND 事件类型命中 AND (keywords 为空 或 命中任一) AND (无法命中 excludes)
```

**组内 OR / 组间 AND** 是用户唯一能自然理解的心智模型（"包含 A 或 B，但不要 C"），所以词表是 OR、维度之间是 AND；`排除优先` 让"看全部但躲开噪声"成为一条最短路径——加一个排除词就够，不必先把关键词收窄。

### 3.3 唯一判定点

沿用既有约定：**判定只在 `TrafficFilter::Matcher::accepts(record)` 一处实现**。`FilterBar` 只做条件收集，一行匹配逻辑都不写；测试与低频场景用一次性入口 `TrafficFilter::accepts(record, options, format)`（内部就是临时构造一个 `Matcher` 再调用，同一份实现）。

`Matcher` 在**条件变更时构造一次**（`updateFilter()`），构造期把该预编译的都编译掉，热路径只做判定：

1. **词表预编译**：`keywords` / `excludes` 的每一项在构造期变成 `TextCondition`——正则模式下 `QRegularExpression` 只编译一次，热路径只 `match()`。**非法正则的那条条件直接丢弃**（条件条标红提示），而不是退化成字面串匹配：退化的方向必须是"不过滤"，宁可多显示，也绝不因为写错一个括号把整屏数据静默吞掉。
   - 坑：默认构造的 `QRegularExpression` 是**有效且匹配一切**的，所以"这条是不是正则"必须用显式的 `bool m_regex` 记住，不能拿 `pattern.isValid()` 当判据（踩过一次：所有字面条件静默退化成匹配一切）。
2. **候选文本按"便宜 → 昂贵"排序 + 逐项短路**：对端地址、端点名、状态文本、详情、当前格式渲染文本、UTF-8 渲染文本、紧凑 HEX、带空格 HEX；后两项最贵，而只要前面的便宜项命中就直接返回，**多数消息上两条 HEX 串根本不会被构造**（现状 `accepts` 无条件构造两次 HEX，是既有的可优化点）。
   - **这条候选表决定了一个语义边界（r6 实测）**：表里没有"DEC / BASE64 / 转义字节的格式无关原样候选"，只有"当前格式渲染文本"。因此**只在某格式专属渲染里命中的条件**（例：格式为 DEC 时搜 `255`，命中的是 `0 255` 这种渲染）会**随编码格式移动命中的行**。外观重投影按当前格式重建已应用判定器（`Matcher(m_projectedOptions, currentDisplayFormat())`），所以这是"**同一条件在新渲染下的重新求值**"，不是"把未应用的条件套上了历史"——判别依据：`m_projectedOptions == m_filterOptions` 期间「应用过滤」提示始终干净。要让它严格不变，就得给每种格式都留一份候选（成本与"所见即可搜"都不可接受），故按边界记录、不修。
3. **排除优先**：`excludes` 先判，命中即刻否决，再判 `keywords`。

这三个约束合成一句话：**判定成本与"条件数量"线性，与"文档行数"完全无关**——条件变更时才付一次编译成本，之后每条消息只走一遍短路比较。

## 4. 过滤与"搜索"的关系（已确认：合并）

搜索框升级为过滤的一部分，不再有第二套语义：

- 搜索框 = `keywords` 的快捷输入（**逗号分隔**多个条件，全部 OR）；
- 关键词输入就是把 `keywords` 直接放在条上（不再额外画 chip：输入框本身就是条件唯一的样子，多一份可视副本只会多一处要同步的状态）；
- 保留独立输入框的原因是**高频快捷键位**：`Ctrl+F` 聚焦、改完回车即收流，不必进浮层。

**分隔符用逗号而不是空格**：这个工具的常见内容是 HEX，"AA 55" 这种**带空格的一条条件**必须能原样表达；拿空格当分隔符会把它拆成两条更宽的独立条件（`AA` 与 `55`），把整屏都放进来——这是"看起来在过滤、实际几乎没过滤"的隐蔽错误。逗号分隔还允许一条条件里出现任意空格，解析规则只有一条（`splitConditions`：按逗号切、trim、去空、去重）。

## 5. 生效时机（关键决策）

F1 时的取舍（保留作沿革；r5 之后 A 被"外观自动重投影"取代，B 仍是过滤条件的路径）：

| 方案                      | 行为                            | 成本                                                                        | 数据源                          | 结论                                                           |
| ----------------------- | ----------------------------- | ------------------------------------------------------------------------- | ---------------------------- | ------------------------------------------------------------ |
| **A. 仅新行**（到达时判定）        | 改条件只影响之后到达的行                  | 0                                                                         | —                            | F1 落地为控制台语义的基线；**r5 废止**——外观改为视图属性，见下    |
| **B. 显式回溯**（`应用过滤`按钮）   | 点按钮：清空视图 → 从模型重放命中项 | 清空是一次整块释放；重放成本只与缓冲条数有关（6.9 µs/条），r6 后缓冲默认不设小上限，所以**跑到安全阀附近的会话会是秒级** | `TrafficModel`（r6：512 MiB / 2000 万条安全阀） | **F1 落地、r5 提预算、r6 去上限**：过滤条件仍走这条；覆盖范围是"缓冲内全部"，tooltip 与摘要都按这个口径写 |
| C. 全量回溯                 | 理想语义                          | 把文本视图那 400 万块 / 5.12 亿字符的规模也留成结构化历史（每条 Message 带时间、来源、三个 QUuid、两个 QString）≈ GB 级 | 新增 second store              | 否决。注意否决的是"**文本级**规模的结构化历史"，不是"留一份结构化历史"——r5 恰恰留了；r6 只是把它的上限从"5 万条"抬到"内存安全阀"，没有取消这条边界 |

**决策（r5 定稿）：视图是投影，两条路径分工。**

| 变化的是什么            | 例子                        | 生效方式                              | 为什么这样分                                    |
| ----------------- | ------------------------- | --------------------------------- | ----------------------------------------- |
| **外观**（每行长什么样）   | 行号/时间戳/方向/长度/HEX 对照/纯数据、编码格式 | **立刻自动重投影**（50 ms 防抖）→ `reprojectView(announce=false, applyCurrentConditions=false)`：**用上次已应用的条件重放**，只换每行的长相 | 一次点击一个状态，用户期待"切了就变"；连点由防抖合成一次，不会连打。**不把未应用的条件套到历史上**（r6 修订，见 §10 决策 1）；已知边界：只在格式专属渲染里命中的条件会随编码格式移动命中的行（§3.3） |
| **过滤条件**（哪些行进来）  | 关键词 / 排除词 / 大小写 / 正则、方向与事件开关、A/B | **只作用于新行**；点「应用过滤」（或回车）才补到已有记录 | 可能是连续输入，每次输入都重画几万行既贵又晃眼；用户也明确给了"按钮一次应用"的形态 |

两条路径共用**唯一一个渲染入口**（`TrafficTextView::appendMessages`）：增量 = 对新一批调用一次，重投影 = `clearAll()` 之后对命中项调用一次。没有第二套渲染逻辑，所以"新行"和"重画的行"在像素上必然一致。

r5 相对 F1 改掉的是三件事，逐条记下原因（避免以后被当成"退化"又改回去）：

1. **"行按到达时固化"不再成立**。F1 里这条是控制台语义的基石，代价是"切显示开关只影响新行"——用户认为这不可接受，实测也证明重排很便宜（6.9 µs/行），所以外观改为视图属性。
2. **"只回溯模型保留范围"要先说清范围**。F1 用 2 万条 / 4 MiB，tooltip 里写着"只回溯最近 2 万条"。r5 提到 **5 万条 / 16 MiB**（原文四倍），措辞从"最近 2 万条"改成"缓冲范围内全部"——用户的诉求正是"为**当前所有已到达的数据**应用"，那么边界就必须说得准确。**r6 之后**这个边界退到安全阀位置，tooltip 相应改成"缓冲内全量重放，不设条数上限"。
3. **代价从"小"变成"要点一下"**。过滤条件不再自动重排已有行，所以必须把"条件改了但还没应用"这个状态显式说出来：按钮文字变成 `应用过滤 •`、tooltip 变成"点这里把条件应用到全部已到达的数据"，状态栏也会播报重投影条数。不提示的话，用户只会看到"我改了条件，屏幕没动"，然后判断成坏了。

落地时的四条约束：

- 按钮 tooltip 写明覆盖范围：`把当前过滤条件应用到已经收到的全部记录（缓冲内全量重放，不设条数上限）`——不做无声的"半回溯"；
- 重投影后摘要播报 `已按当前条件重投影：显示 N 条（缓冲 M 条内匹配）`，让用户知道视图刚被换过；
- 行号从 1 连续重排（清空与重放是同一个动作的两半，中间不能留旧行号，否则"第 3 行"会指向两条不同的记录）；
- **在翻阅历史时重投影不要把用户弹回顶部**：先记下滚动位置的比例，重投影后按比例放回；跟随模式下照旧钉底。需要更长历史的用户另一个出口是"记录到文件"（全量落盘，不受过滤影响）。

**模型空时按钮置灰**，不做"点了没反应"。置灰状态在 `updateSummary()` 里按 `model->rowCount()` 刷新，并带一次"值没变就不碰控件"的短路——`updateSummary` 在每批入模后都会跑，热路径上不能引入无谓的样式重算。

### 5.1 为什么不做"条件也自动生效"

把过滤条件也做成自动（输入防抖）一度是最省事的统一规则，最后否掉：

- **成本不可控**。缓冲 5 万条时一次重投影约 350 ms。连续输入"心 → 心跳 → 心跳,temp"会触发多次 350 ms 的重画；用户刚提的要求恰恰是"大量数据时，时刻可以保证马上刷新出来"，自动重画把"什么时候卡"变成了不可预测。
- **阅读位置会被反复夺走**。虽然做了滚动位置恢复，但连续重画对正在读历史的人是纯干扰。
- **用户给的形态就是按钮**。既然显式应用能满足需求，就没有理由替用户决定"什么时候该重画"。

### 5.2 为什么不做方案 C（把结构化历史提升到与文本同级）

否决理由不变，但边界要说准：否决的不是"留一份结构化历史"（r5 恰恰这么做了），而是"**把文本视图那 400 万块 / 5.12 亿字符的规模也留成结构化历史**"——那才是 GB 级。r5 的做法是把缓冲预算收敛到"重投影还能点一下就有"的量级（5 万条 / 16 MiB），用**明确的预算**换**确定的响应时间**；**r6 撤回了这个取舍**：用户要的是"不丢数据"（JCom 的语义），于是历史长度优先、响应时间让位——安全阀只在内存告急时生效，且必然播报。

## 6. 性能预算与实现要点

- 每条消息判定：条件数 × 短路；典型 < 1 µs。**必须**保证：
  - 正则表达式在条件变更时用 `QRegularExpression` 预编译一次，热路径只 `match()`；
  - HEX 串**惰性构造**——只有存在"内容按 HEX 匹配"的条件时才把 `raw` 转成 HEX（现状 `accepts` 无条件构造两次 HEX 串，是既有的可优化点）；
  - 被禁用（未勾选）的条件不参与判定；
  - 长度条件是整数比较，不构造字符串。
- 明确不做：按行扫描文档、全表高亮、每条消息重建视图、为过滤复制一份原始字节。
- 命中高亮（F2）：只对**新追加的行**做，代价 O(命中数)；不对历史全表重刷。
- 计数：新增 `m_filteredOut`（被条件挡下的条数），状态栏摘要变为"共 N 条 · 过滤掉 M 条"，同时把"过滤生效中"体现在状态栏（避免用户以为掉数据）。
- perf 基准新增场景（**F2**）：`--filter 5`（5 个条件全开）下的净工作耗时，门槛沿用 < 10 ms/拍。F1 的判定路径已按上面的短路口径实现（条件数线性、与行数无关），补基准与 F2 的新条件维度一起做。

## 7. 交互设计

### 7.1 形态：两行头（顶栏 + 可折叠内容条件条）

过滤条不占独立的一"块"，它是**监视区头的第二行**，与顶栏同处一个头块（行距 6px）：纵向成本就是一行控件的高度。默认展开，由顶栏的 `过滤` 按钮折叠——**折叠只隐藏第二行（内容条件），条件照常生效**。

```text
┌ 监视区 ─────────────────────────────────────────────────────────────────────────────────────────┐
│ [A][B] [UTF-8 ▼] [⚙过滤 · 3 ▾] [↓RX][↑TX] [◌纯数据模式][#同时显示 HEX][↵自动换行]  [⚙显示设置][导出][↓滚动到底][清空] │ ← 顶栏（常驻）
├─────────────────────────────────────────────────────────────────────────────────────────────────┤
│ 🔍关键词[心跳,AA 55 ▏] │ ⊖排除[error ▏] │ Aa区分大小写 │ .*正则表达式 │ ⟳应用过滤 │ ⊘              │ ← 内容条件条（可折叠）
├─────────────────────────────────────────────────────────────────────────────────────────────────┤
│ 1  14:30:01.201 [4 B] RX: 01 02 03 04                                                           │ ← 数据区
└─────────────────────────────────────────────────────────────────────────────────────────────────┘
```

折叠后只剩顶栏一行（数据区上移）：**方向开关与显示开关仍在原位**（它们常驻顶栏），"过滤 · N" 的计数也仍在报警：

```text
│ [A][B] [UTF-8 ▼] [⚙过滤 · 3 ▸] [↓RX][↑TX] [◌纯数据模式][#同时显示 HEX][↵自动换行]  [⚙显示设置][导出][↓滚动到底][清空] │
```

五条形态约束：

- **第二行恒为一行**：与顶栏那一行等高（内联控件走同一套 18px 最小高度 / 4px 内边距规格，与端点行同一约定），不随窗口宽度、也不随条件数量变化；数据区不会被它挤动。
- **宽度铺满**：关键词输入框是唯一弹性项，吸收全部剩余宽度，其余元素按自身 `sizeHint` 紧凑排在右侧；**永不换行、永不出现横向滚动条**。
- **可折叠但不失效，且折叠范围明确**：`过滤` 是可勾选按钮（勾选 = 展开），文字恒带生效条件数；折叠用 `▸`、展开用 `▾`。**折叠只收起"内容条件"那一行**，顶栏的方向开关（"哪些行进来"里调频次最高的一组）与显示开关（"每行长什么样"里调频次最高的一组）都不受影响。
- **按钮一律带 Material 字形**（用户钦定）：字形取自 `@mdi/svg 7.4.47`，与既有 `cog.svg` / `arrow-down.svg` 同源、同一套 16px 尺寸。
- **零新增自绘**：元素只用 QSS 已覆盖的 `QPushButton` / `QLineEdit` / `QMenu`，不新增自绘控件、不写死像素。

**关于原顶栏搜索框**（修订已确认决策 #3 的形态）：关键词就是过滤条的第一格，顶栏不再重复放一个搜索框——搜索框原本占据顶栏唯一的弹性位置，把它连同"关键词"语义一起下移到过滤条，等于用同一行高度换到一整行的可用宽度；腾出的位置给了 `过滤` 折叠按钮、紧随其后的方向开关（r7 之后又跟上了显示开关）。`Ctrl+F` 行为不变（必要时先展开再聚焦），`Ctrl+Shift+F` 展开/收起第二行。

### 7.2 条件条的解剖（按位置分两组）

**顶栏那组（常驻）**——从左到右紧跟在 `过滤` 按钮之后，前两个由 `FilterFlags` 持有、后三个由 `ViewToggles` 持有（后者是显示设置菜单同名 `QAction` 的门面）：

| 元素     | 字形（Material）              | 文案          | 宽度策略 | 说明                                    |
| ------ | ------------------------ | ----------- | ---- | ------------------------------------- |
| `过滤 · N ▾` | `filter-variant`         | 有           | 定宽   | 唯一折叠入口；勾选 = 展开，N = 生效条件数（两组合计）         |
| RX     | `arrow-down-bold`        | `RX`        | 定宽   | 显示接收                                  |
| TX     | `arrow-up-bold`          | `TX`        | 定宽   | 显示发送                                  |
| 纯数据模式  | `format-clear`           | `纯数据模式`     | 定宽   | 去掉一切行前缀，只显示数据本身（r7 起常驻顶栏）             |
| 同时显示 HEX | `numeric`                | `同时显示 HEX`  | 定宽   | 数据行之后另起一行显示 HEX 对照；HEX 显示格式下自动省略       |
| 自动换行   | `wrap`                   | `自动换行`      | 定宽   | 按窗口宽度折行；关闭时长报文水平滚动（r7 起常驻顶栏）          |

**状态 / 警告 / 错误**（事件类型开关）**不在顶栏**（r7）：它们是"显示设置"菜单里的 `QAction`（`showStates` / `showWarnings` / `showErrors`），与菜单里那批行内容选项同类。它们照样参与过滤计数与"重置"，只是不再占顶栏的位置。

**第二行那组（可折叠，`FilterBar`）**：

| 元素       | 字形（Material）               | 文案          | 宽度策略        | 说明                                              |
| -------- | ------------------------- | ----------- | ----------- | ----------------------------------------------- |
| 关键词输入    | `magnify`（前导）             | placeholder | **弹性（吸收余量）** | **逗号分隔**多个条件、任一命中（OR）；`Ctrl+F` 的落点；无清除按钮（✕）    |
| 排除词输入    | `minus-circle-outline`（前导） | placeholder | 定宽，最小 8em   | 逗号分隔，命中即隐藏（黑名单），优先于关键词                          |
| `区分大小写`  | `format-letter-case`      | 有           | 定宽          | 勾选型按钮，**就摆在条上**（原先收在 `更多` 浮层里）                  |
| `正则表达式`  | `regex`                   | 有           | 定宽          | 勾选型按钮；表达式无效时该条件不参与过滤                            |
| `应用过滤`   | `filter-check-outline`    | 有           | 定宽          | 把当前条件应用到**已收到**的记录上（显式回溯，见 §5）；模型为空时置灰         |
| 重置       | `filter-off`              | 无           | 定宽          | 清空**全部**条件（含顶栏那排开关），回到不过滤；无条件时置灰               |

**为什么不做 chip、不做下拉**（用户钦定，两条都简化了交互）：

- **chip 去掉**：chip 是"输入框文本的第二种视图"，两份视图就要同步，同步就会有先后与时机问题；而这个条子上的条件本来就短（几个词/几个 HEX），输入框自己看得见、能全选重输。少一份状态就是少一类 bug。
- **输入框不带清除按钮（✕）**：`clearButtonEnabled` 的 ✕ 与"改完即生效"两个入口会互相干扰（改到一半误点就清空全部条件），而全选重输（或 `Ctrl+F`）本来就更快。
- **`更多` 浮层去掉，匹配选项直接摆出来**：一个布尔条件 = 一个按钮，比"下拉 + 浮层"少一次点击，还让"当前是不是在按正则匹配"**一眼可见**——收进浮层的东西，看不见就等于不存在。这也是整个过滤区第二次按下拉（第一次是方向/事件开关从菜单迁出）。

**字形与文字的取舍**：判据是**字形是否唯一指向该动作**。这排按钮横向余量够，所以一律**字形 + 文案**；只有 `重置` 是纯字形 + tooltip，因为它只有一个含义且已经有 `filter-off` 这个自解释的字形。

**勾选按钮的字形要手动换色**：`QPushButton` 的图标状态位跟的是"按下"而不是"勾选"，勾选态必须按 `toggled` 显式换成与 QSS 选中文字同色的深琥珀。这个模式在顶栏开关与条上的匹配选项里都要用，已抽成 `bindToggleIcon()`（`ui/common/tintedicon.h`）——一份实现防住"琥珀底上出现灰字"这一个错。

**单一状态源**：`RX / TX / 状态 / 警告 / 错误` 五个开关只有一份状态，**常驻顶栏**（已从"显示设置"菜单迁出，再经一次修订从第二行提到顶栏）。原"显示错误日志"这一个布尔拆成 `状态 / 警告 / 错误` 三个独立开关，`TrafficFilter::Options` 里的 `events` 由三者取代。控件 objectName：`filterRx` / `filterTx` / `filterState` / `filterWarning` / `filterError`，统一由 `FilterFlags`（`src/ui/panels/traffic/filterflags.{h,cpp}`）持有。

**为什么这五个开关不进可折叠的第二行**：它们不是"低频维度"。真实使用里"只看错误"、"只看接收"是最高频的两种收窄动作，而关键词与排除词往往一次设完就不动——把高频的藏进折叠区、把低频的摆在常驻行，正是反的。第二行因此只承担**内容条件**（关键词 / 排除词 / 匹配选项 / 应用过滤），与"重置"一起构成"这次要滤什么内容"的一组。

**跨控件的收尾**：条件分散在两个控件里，"重置"必须是整套动作——`FilterBar` 清空自己的内容条件后发 `resetRequested()`，由面板把 `FilterFlags` 一并复位；反过来，只关掉 RX（内容条件为空）时重置按钮必须仍可用，所以 `FilterBar::setResetAvailable()` 由面板按两处合计的计数刷新。同一条思路还有 `setRebuildAvailable()`：能回溯与否取决于模型里有没有记录，也只有面板知道。

### 7.3 宽度预算与折叠规则

**下限由控件自己声明，不由谁手工求和**（r7 修订）。头两行"最少要多宽"= 行里每个控件都能完整显示自己之和（含内边距、间距、边框）。这个和不需要算：给行里每个非弹性控件设横向策略 `Fixed`（语义就是"布局按我的 sizeHint 给我位置，别缩我"），行容器的 `minimumSizeHint()` 自然就是正确答案，并随字体 / DPI / 翻译 / 文案变化自动跟随。`ui/common/rowmetrics.h::pinRowToContents()` 就干这一件事，`MainWindow` 直接取 `dataArea->minimumSizeHint().width()` 作为数据区下限。

> 这条修订来自一次真实的账目错误：早先由 `TrafficPanel::filterRowWidthHint()` 逐项求和、再加 `DataAreaSideMargin` 手算边距，漏掉了面板自身的 20px 内边距——于是窗口已经到最小宽度，顶栏最右的 `扩展` 按钮仍差 1px 探出右缘。**手工求和的每个加法项都是一次对账机会，而这类错误不报错、只在特定窗口宽度上显形。** 让控件声明、让布局汇总，项数就归零了。

**第二行（内容条件条）**：

| 可用宽度 | 形态                                         |
| ---- | ------------------------------------------ |
| 宽    | 全部摊开：关键词（吸收余量）+ 排除 + 区分大小写 + 正则 + 应用过滤 + 重置 |
| 窄    | 关键词输入压到下限（`charWidth × 15`，跟着字体走，不是写死的像素）；其余元素按自身 `sizeHint` 紧凑排列 |
| 更窄    | 用户自行折叠第二行（`过滤 · N ▸`），条件照常生效                 |

去掉了 chip 与 `更多` 浮层之后，第二行的固定宽度基本没变（chip 只在前 3 个词时才出现，`更多` 与两个匹配选项按钮宽度相近），但**弹性项更干净**：现在只有关键词输入一项吸收余量，边界情况（三种 chip 数量 × 两种浮层计数）一次都没有了。

**顶栏**（这排开关常驻的代价落在这一行）：`A/B + 编码 + 过滤 · N + RX/TX + 纯数据模式/同时显示 HEX/自动换行 + 显示设置 + 导出 + 滚动到底 + 清空 + 扩展` 必须排得下——判断标准是**相邻元素不重叠、最右元素不被切掉**，由 `topRowSwitchGroupsStayPut` 用例在**窗口自己的最小宽度**下逐对几何量测兜底（并额外断言这个最小宽度不超过 `MaxSaneWindowWidth`：下限是"内容不被压缩"的代价，但超过屏幕宽度就把"加宽窗口"变成了"跑出屏幕"）。为此这一行按钮的左右内边距比通用按钮各收紧 3px，条件条上的 `区分大小写` / `应用过滤` 用同一条规则。

**不按宽度动态把按钮搬进浮层**：那需要两套排布加一次判据，收益只有几十像素；把"更窄"交给用户手上的折叠按钮更直接、更可预期，也让布局只有一种形态可测。硬规则不变：**两行在任何宽度下都保持单行**——`QHBoxLayout` 只会压缩，永不换行、永不出现横向滚动条。

### 7.4 与"显示设置"的分工

| 面板   | 管什么        | 例子                                 |
| ---- | ---------- | ---------------------------------- |
| 显示设置 | **每行长什么样** | 行号、时间戳、方向、长度、HEX 对照、纯数据、自动换行、记录到文件 |
| 过滤   | **哪些行进来**  | 关键词、排除词、方向、端点、事件类型、长度、对端、帧类型       |

按这条线重新归位：**`RX` / `TX` / `状态` / `警告` / `错误` 从"显示设置"菜单迁入过滤区**（它们管的是"哪些行进来"，原本放错了地方），显示设置菜单随后只剩行内容开关与"记录到文件"，反而更短。`A` / `B` 端点开关仍留在顶栏左端（高频、且属于范围而非条件），过滤区不重复它们。

归入过滤之后，这五个开关又细分为两层：**顶栏常驻**（方向，高频）与**第二行可折叠**（内容条件，低频但占宽）。分层依据是调频次，不是数据的种类。

**r7 的再平衡**：事件开关（状态/警告/错误）虽然管的是"哪些行进来"，但它们在顶栏的位置被调用频次更高的**显示开关**（纯数据模式 / 同时显示 HEX / 自动换行）取代了——顶栏第一行的宽度是有限的（见 §7.3），位置必须给最高频的一组。事件开关退回"显示设置"菜单，与那里同类的行内容选项放在一起；**"哪些行进来"由谁管**这条语义边界没有变，变的是三个开关画在哪。它们是 `QAction`，照样进过滤计数与"重置"。代价是"只看错误日志"从一键变成两步（点开菜单再点一项）——用户认可这个交换。

**外观（每行长什么样）改了就立刻重排已收到的内容（自动，50 ms 防抖）；过滤条件只作用于新行，要补到已有记录上就用第二行的 `应用过滤`**（见 §5）——后者是唯一会动已有行的入口。

### 7.5 反馈

- 条数摘要：`共 12,043 条 · 过滤掉 8,912 条`（进主窗口状态栏，不占面板空间）。过滤是"静默少显示"，必须有一个能证明"数据没丢、只是被挡住"的数字。
- **顶栏折叠按钮承载计数**：文字恒为 `过滤 · N ▾`（N = 生效条件数，**跨顶栏开关与第二行内容条件合计**），收起时变 `过滤 · N ▸`；N 为 0 时省掉数字。这个计数在收起状态下尤其重要——它说明第二行虽然看不见了，但里面还有 N 条内容条件在生效。
- **"改了还没应用"必须说出来**：过滤条件改动后屏幕上不会自己变（这是刻意的，见 §5），所以按钮文字变成 `应用过滤 •`、tooltip 改成"点这里把条件应用到全部已到达的数据"，状态栏也播报重投影条数。不提示的话，用户只会看到"我改了条件，屏幕没动"，然后判断成坏了。
- 条件本身不画 chip：输入框就是它唯一的样子（见 §7.2）。
- 正则非法时输入框红框 + 提示，且**该条件不参与判定**（退化为不过滤，绝不静默吞掉全部数据）。
- 空态提示随之变化："当前过滤条件下没有匹配记录 / 已挡住 N 条"，而不是"等待接收数据"——顶栏与第二行的条件都算数。
- `应用过滤` 在模型还没有记录时**置灰**，不做"点了没反应"。

## 10. 已确认决策（2026-10-04）

| #  | 议题     | 决策                                                    | 影响                                                                            |
| -- | ------ | ----------------------------------------------------- | ----------------------------------------------------------------------------- |
| 1  | 生效时机   | **视图是投影：外观改了就自动重投影（防抖），且只重排、不换条件**——外观路径用**上次已应用的条件**重放（`applyCurrentConditions=false`），绝不把未应用的条件套到历史上；**过滤条件只作用于新行，靠 `应用过滤` 显式应用**；**清空是会话边界**，以当前条件为新会话的已应用基线 | 显示设置立刻作用于已收到的内容；过滤条件的重画时机由用户掌握；「应用过滤 •」在"条件改了没应用"期间保持可见（包括连点外观开关之后）；重投影成本 6.9 µs/行。已知边界：只在格式专属渲染里命中的条件会随编码格式移动命中的行（§3.3，属同一条件的重新求值） |
| 2  | 编辑入口   | **顶栏 `过滤 · N ▾` 折叠按钮 + 第二行内容条件条**                     | 按钮只管展开/收起第二行并承载生效条件数（两组合计）                               |
| 3  | 搜索框关系  | **合并为同一份 `keywords`**（形态见 #5）                         | 无第二套语义；关键词输入框落位在条件条第 1 格；`Ctrl+F` 键位不变                              |
| 4  | 记录到文件  | **保持全量，不跟随过滤**；**三个会话边界都重开新文件**（程序启动 / 清除视图 / 手动开启） | `writeLog` 仍在过滤之前，模型安全阀裁剪不影响已落盘内容；导出则尊重当前视图（所见即所导）。重开 = 新建 `<模板基名>-yyyyMMdd-HHmmss.<扩展名>`（同秒撞名 `-2/-3`），**不覆盖、不追加**；`m_logPath` 仍是持久化的"模板路径"，实际写入路径另存。文件头写 `# easyDebug <时间> 格式=<X>`，记录期间切格式插 `# 格式切换 → <X> <时间>`（记录格式仍跟随显示格式，故这两行是事后唯一的判断依据）。数据行格式不变：`时间\t端点\t对端\t方向\t内容\n` |
| 5  | 过滤区形态  | **两行头 + 可折叠第二行**：顶栏常驻、第二行高恒为一行、宽铺满、默认展开、可折叠且条件照常生效 | 过滤区高度由约 5 行降到 2 行；原顶栏搜索框迁入条件条；`RX/TX` 从"显示设置"菜单迁出（单一状态源） |
| 6  | 开关落位（r7 修订） | **方向开关（RX/TX）+ 显示开关（纯数据模式 / 同时显示 HEX / 自动换行）常驻顶栏**，紧挨 `过滤` 按钮，不进可折叠的第二行；**事件开关（状态/警告/错误）留在"显示设置"菜单** | 折叠只收内容条件；调频次最高的一组（只看接收 / 切显示形态）永远一键可达；代价是顶栏要按最小窗口宽量宽度（见 §7.3），"只看错误"多一步 |
| 7  | 按钮字形   | **全部按钮带 Material 字形**（`@mdi/svg 7.4.47`，与既有 `cog.svg` 同源同尺寸） | 过滤区横向余量够，一律**字形 + 文案**；只有 `重置` 是纯字形 + tooltip；勾选态需显式换色（`bindToggleIcon`）  |
| 8  | 非法正则   | **丢弃该条件**，不退化为字面匹配                                     | 退化方向必须是"不过滤"；条件条标红提示；见 §3.3/§7.5                                              |
| 9  | 历史长度（r6） | **不设小预算：上限只做内存安全阀**（模型 512 MiB / 2000 万条，文本 400 万块 / 5.12 亿字符）；**触顶释放必须进状态栏摘要，只在状态栏、不插日志标记行** | 代价是跑到安全阀附近的会话重投影为秒级；换来 JCom 式"数据不丢"。用户在同一份压测下对比 JCom 后钦定 |
| 9  | 条件分隔符  | **逗号**（不是空格）                                           | HEX 条件常含空格（`AA 55`），空格分隔会把它拆成两条更宽的条件；解析只有 `splitConditions` 一处        |
| 10 | 输入框反馈  | **不做 chip、不带清除按钮（✕）**                                  | 条件只有"输入框"这一份状态；避免"误点 ✕ 清空全部条件"与"改到一半被 ✕ 打乱"                                  |
| 11 | 匹配选项   | **`更多 ▾` 下拉去掉，两个布尔条件直接摆成条上的按钮**                       | 少一次点击；"当前是不是在按正则匹配"一眼可见——看不见就等于不存在                                            |

实施顺序：**F1 ✅**（关键词 / 排除词 / 方向 / 端点 / 事件类型 + 两行头可折叠条件条 + 逗号分隔 + 匹配选项按钮 + 应用过滤 + 持久化 + 过滤计数）→ F2（长度 / 对端 / 帧类型 / 来源 + 命中高亮）→ F3（命名预设）。
