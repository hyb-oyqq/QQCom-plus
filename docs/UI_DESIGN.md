# 界面与端口控件设计

状态：固定双端点工作台已实现，真实通信尚未接入。当前实现用于验证布局、交互和数据模型；首版采用 Qt Widgets，默认中文，字符串使用 tr() 保留翻译能力。

## 1. 工作区布局

```text
┌──────────────────────────────────────────────────────┬──────────────────┐
│ A [串口     ▼] 串口   [COM3 · CH340   ▼] 115200▼ │ [A → B      ▼]  │
│                                      ≡高级   [连接]   │ [⇄ 建立桥接]    │
│ B [TCP服务器▼] 本地地址[127.0.0.1     ▼] 监听端口[9000]│                 │
│                                      ≡高级   [监听]   │                 │
├──────────────────────────────────────────────────────┴──────────────────┤
│ [示例数据] [HEX ▼] [搜索文本/HEX/端口……………] [⚙显示设置] [导出] [↓滚动到底] [清空] │
│ 时间          端口/对端  方向 字节 数据内容                              │
│ 14:30:01.201  A          ↓RX   4   01 02 03 04                          │
├─────────────────────────────────────────────────────────────────────────┤
│ 发送区（单页，无页签）                                                   │
│ ┌ 正文输入框 ─────────────────────────────────────────────────────────┐ │
│ └─────────────────────────────────────────────────────────────────────┘ │
│ 格式 [HEX ▼] 编码 [UTF-8 ▼] 末尾 [不追加 ▼]   8 字节  最终字节预览       │
│ □定时发送 [1000 ms] [持续]  端口未连接  目标 [A][B][AB] [发送]           │
├─────────────────────────────────────────────────────────────────────────┤
│ RX / TX 速率与计数  队列积压  转发状态  显示遗漏/记录异常提示              │
└─────────────────────────────────────────────────────────────────────────┘
```

主窗口直接进入工作区，不设置独立品牌栏或顶部操作栏。页面固定只有两个端点，顶部的端点条始终把 A、B 两行完整摊开：每行自左向右是端点徽标、类型下拉框、该类型的全部常用参数、高级开关、行内校验提示、状态文字和连接动作。桥接块竖排在这两行右侧，宽度由自身内容决定、没有独立底色，与端口选择区共用同一张白色面板；方向选择在上、"建立桥接"按钮在下，没有标题。两个端点的参数同时可见可改，不需要先选中某一行再到别处编辑；端点类型可以任意组合，常用场景是串口↔TCP、串口↔UDP、TCP↔TCP。数据监视与下方发送区之间用 QSplitter 调整比例。示例数据仍可通过测试或命令行入口载入，通信状态仍显示为预览状态。

端点条的纵向开销是硬约束：折叠状态下整条不超过 96px（实测 84px，每行 40px 贴合控件自身高度）。因此行内控件使用 18px 最小高度和 4px 内边距，桥接块只有两行且不含常驻提示文字，端点行也不含状态文字或校验图标——它们都会和参数争夺同一行的宽度。

A、B 两行必须对齐：各类型参数页的首个标签共用一个列宽（按最长者计算），因此无论两端选择哪种类型组合，类型下拉框和第一个参数控件的左边缘都在同一竖线上。16 种类型组合都纳入自动校验。首个参数控件（串口下拉框、远端/本地地址）取用该行的剩余宽度，使 `COM3 · USB-SERIAL CH340` 这类友好名称完整可读；更长的名称在行内省略，由下拉列表（上限 640px）和悬停提示补全，不允许反过来撑宽窗口。

这一布局取自参考工程的 `[标识] [类型] [参数] [连接]` 单行形态。取消左侧端点列表和独立的「端口配置」区：固定两个端点时，列表只提供选择功能，而选择本身就是多余的一步，且列表会占走纵向空间。端点行不再承担摘要展示，参数直接以控件形式呈现；`portDraftSummary` 与 `portDraftDetails` 仍用于端点徽标的悬停提示、数据记录和未来的配置导出。

端点行不设独立状态文字：动作按钮同时承担状态与操作。未开启时显示要执行的动作（串口/TCP 客户端「连接」、TCP 服务器「监听」、UDP「绑定」），已开启时显示终止动作（「断开」「停止」「解绑」），并通过 `open` 属性把底色从蓝色切为红色。这样一个控件就说明了当前状态和下一步操作，不需要「未监听 + 监听」这类重复表达。整体运行状态由状态栏汇总。真实通信接入后，连接中、重连等待、错误等中间态同样通过按钮文字加状态栏呈现；`setConnectionOpen()` 是传输层回报状态的入口，通信后端接入前按钮保持禁用。不提供添加、删除和多端点排序。

行内也不放校验提示文字或图标：无效字段本身带红色边框，具体原因在该字段的悬停提示里，`validationError()` 仍汇总全部消息供组合根使用。参数是否完整由桥接按钮的可用性体现。

行内控件的宽度一律由控件自身属性决定，不写死像素值——`118px` 之类的常量在中文、其他翻译或换个字体后会裁掉「TCP 服务器」，而这类裁切在非编辑型控件上没有任何补救手段（选中值直接消失）。具体分三类：非编辑型下拉框用 `fitComboToItems()` 设 `AdjustToContents` 并配 `Fixed` 尺寸策略，由样式表把边框、内边距和画在内边距里的箭头一起算进 `sizeHint()`；数字框由 `PortSpinBox` 覆写 `sizeHint()`，在基础提示上补上样式表的边框宽度，因为 `QAbstractSpinBox::sizeHint()` 不计这一项，`客户端上限`（范围 1～64）曾因此比 `64` 窄 2px；需要跟随行宽的首个参数控件（串口、远端/本地地址）才使用 `Expanding` 加最小宽度，此时文本可编辑或按设计省略，弹出列表与悬停提示补全完整名称。这些宽度都随字体与 DPI 变化，不需要为换肤或缩放重新调常量。

端口设置区的全部控件受一条自动检查约束：`tests/ui` 遍历两个端点、四种类型、折叠与展开状态下的每个下拉框和数字框，用 `SC_ComboBoxEditField`／`SC_SpinBoxEditField` 取出真正的文本绘制区域，断言它容得下当前最宽的可选内容。新增控件若宽度不够会在测试里直接失败，而不是等到人工点开才发现。

悬停提示严格读取该端点的当前类型和草稿，不从当前编辑器或派生标签推断。串口示例为 `COM3 · 115200 · 8N1 · 无流控`：包含端口号、波特率、数据位、校验及停止位，流控非默认时显示 `RTS/CTS` 或 `XON/XOFF`；校验简写使用 N/E/O/M/S，提示中展开中文字段及单位。TCP/UDP 继续显示对应地址和端口。

端点标识不提供可编辑名称：`endpointLabel()` 由行号与该行当前类型派生，例如 `A · 串口`、`A · TCP 客户端`，类型切换后立即更新。桥接摘要与数据记录复用同一个派生标签，因此摘要永远与端点行的实际类型一致，不会出现名称与配置互相矛盾；原「名称」字段已从高级行移除，配置草稿中不再有用户提供的名称。

高级参数就地展开在该端点行下方，只影响这一个端点的高度，不进入对话框、不切换页面。展开时数据区整体下移，监视表和发送编辑器仍须完整可见；1280×720 下两者都不得被挤出窗口，因此数据区的 splitter 按 **7:3** 偏向显示区：初始比例在 showEvent（几何定型后）按实际高度经 `setSizes` 应用一次——`setSizes` 接收绝对像素，传比例数字会被各面板的最小高度钳制成错误比例；窗口缩放时沿用该比例继续分配，仍可拖动调整。折叠状态下若某个高级字段校验失败，该行自动展开，避免错误提示指向看不见的控件。

高级入口是一个纯图标按钮，不再使用 `▸`/`▾` 字符，也不再显示「高级」二字。图标取自 Material Design Icons 的 `tune`（`resources/icons/tune.svg`，Apache-2.0），单一扁平图形，在 C++ 侧用 `SourceIn` 重着色为 QSS 的 `#647590`，展开时换为 `#3465d5`，因此颜色与文字层级一致而不需要为按钮单独改样式表。三条约束固化了这个按钮：图标尺寸在代码里设为 20px，连同按钮自身内边距正好是 28px，与旁边的「连接／监听」按钮等高（测试断言两者高度相等）；`QToolButton::setArrowType()` 会顶掉图标（Qt 中箭头与图标互斥），所以开合状态改由图标配色与面板本身表达；「高级」文字保留在 `text()` 与 `accessibleName()` 中，当 SVG 插件缺失、图标无法渲染时退回文字按钮，不会留下一个空按钮。

全局字体使用系统无衬线字体回退链 `Microsoft YaHei UI`、`Microsoft YaHei`、`Segoe UI`。界面只使用四级文字层级：正文 13px、辅助文本 12px、分区标题 15px、页面标题 18px；数据表和发送编辑器的等宽字体属于数据展示例外，分别固定为 10pt 和 11pt。新增控件必须继承正文大小，不在单个控件上随意设置字号。

## 2. PortSelectorWidget

参考 `portmanager + QComboBox + QStackedWidget` 的组合，已经封装成独立 QWidget：端点徽标、类型选择、横向参数页容器、高级行、参数校验、状态与动作。控件本身就是一个完整的端点行，`MainWindow` 直接实例化两个（objectName 为 `endpointA`、`endpointB`）并通过 `setEndpointLabel()` 指定标识。字段的 objectName 在实例内唯一，跨实例查找须先定位到对应的 `PortSelectorWidget`。

常用参数与高级参数由两个同步切换的 `QStackedWidget` 承载：主行放该类型打开连接必需的字段，高级行放低频参数（串口的数据位/校验/停止位/流控、TCP 客户端的连接超时、TCP 服务器的客户端上限）。两个栈都把非当前页的尺寸策略设为 Ignored，否则行高会被最宽的隐藏页撑开。标签与控件在行内横向排列并垂直居中，不再使用分散对齐的标签列。当前控件只维护端口草稿，不持有通信对象。

`setSerialPorts()` 可能使草稿失效（设备被拔出），因此它在刷新后同样发出 `configurationChanged`；组合根据此重新判定桥接是否可启动，不能只更新字段外观。

输入校验分为输入限制与完整性检查：波特率保留预设及自定义输入，仅允许十进制数字，范围为 1～2147483647（实际硬件支持情况由通信后端打开时确认）；端口、超时、客户端数量使用带范围的数字控件。全局数字输入框（含定时发送间隔、次数）统一隐藏增减按钮，Qt 数字控件设置 `QAbstractSpinBox::NoButtons`，保留直接输入、数值范围校验及单位显示。键入、粘贴及输入法提交均接受校验。监听/UDP 地址校验 IPv4 的四段 0～255，TCP 远端额外允许主机名；UDP 目标可为空以支持仅接收。必填空值、未完成地址和无效配置通过字段边框及文字说明提示，修正后清除提示；加载草稿时同样校验，未来连接入口必须检查配置有效性。

控件接受 EndpointConfig 和 StateSnapshot，发出 configEdited、openRequested、closeRequested 等意图；不持有通信对象。配置页注册表使用稳定的 PortType 标识，翻译、排序或增加页面不改变配置含义。通过 setCurrentWidget 切换页面，不使用 index+1 等隐含占位规则。

| 页面 | 常用项 | 高级项/状态 |
| --- | --- | --- |
| 串口 | 端口名＋描述、波特率、刷新 | 数据位 5/6/7/8、校验、停止位、流控；序列号/VID/PID；实际参数应用失败的原因 |
| TCP 客户端 | 远端地址/主机名、远端端口 | 连接超时、重连开关、退避状态、可选低延迟选项；默认直连 NoProxy |
| TCP 服务器 | 本地绑定地址、监听端口 | 最大客户端数；peer 列表（地址、连接时间、收发、积压）；指定/全部发送、断开选中客户端 |
| UDP | 本地地址/端口、固定目的 IP/端口 | 最近来源列表、选择某来源作为目的地址、广播开关、最大数据报长度 |

首次配置 TCP Server/UDP 默认绑定 127.0.0.1，列表提供“所有网卡”及实际网卡地址；监听所有网卡由用户选择。本地端口 0 表示自动分配，绑定成功后展示实际端口。UDP 可只接收，未选择目的地址时禁用发送。

串口列表将系统标识存入 itemData，描述文字可变化；刷新保留用户选项，消失项标为“设备不可用”。后台刷新结果不触发自动重开。开始连接后锁定类型及影响链路的参数，允许“取消连接”；参数修改在关闭后生效。

当前串口选择已接入真实设备发现：启动时扫描一次，之后由组合根的定时器每 2 秒自动扫描，设备插拔无需手动操作（离屏实例——`--snapshot` 快照与自动化测试——不轮询硬件）。扫描由 `PortDiscoveryService` 在线程池调用 `QSerialPortInfo::availablePorts()`，列表快照只在真正变化时发布，避免重建下拉框打断浏览；界面显示 `COM3 · USB-SERIAL CH340` 形式的名称，描述缺失时使用制造商或"串口设备"。下拉框不可任意输入，配置只保存 `itemData` 中的端口号。扫描不自动选择第一项；所选设备拔出后保留端口号并提示不可用，重新扫描发现同一端口号后恢复可用。长名称通过下拉列表和悬停提示查看。此处端口号身份只服务于配置草稿，运行时仍需独立的会话 generation 校验。

TCP 客户端远端、TCP 服务器本地、UDP 本地/目标地址均使用可编辑历史下拉框，继续执行原有地址校验。历史在编辑完成、选择历史项、切换端点或退出时提交，逐字输入及无效/未完成内容不入库；加载配置不写入历史。远端与本地历史分开保存，各保留最近 20 条并去重；TCP/UDP 共享远端 IP，TCP 额外允许主机名，UDP 列表过滤主机名。默认项保留 `127.0.0.1`，本地绑定额外保留 `0.0.0.0`。更新历史只更新候选项，不改变其他端点当前输入或自动打开连接。

控件发出 `addressCommitted` 意图，组合根连接 `PreferencesStore` 完成存储，再通过 `setAddressHistory` 下发候选项。历史属于用户级轻量偏好，保存在 `QStandardPaths::AppConfigLocation/preferences.ini`；当前工作区的端口配置仍属于未来的 `SessionStore`。UI 不直接操作 QSettings 或枚举硬件。

## 3. 状态与错误反馈

用文字加图标区分“关闭、连接中、已连接、监听中、已绑定、重连等待、关闭中、错误”。颜色仅为辅助，不把 TCP listener 或 UDP bound 显示成“已连接远端”。

参数错误在字段附近显示，运行错误在状态区给出原因和重试入口；重复错误合并并显示次数，避免连续模态 QMessageBox 阻塞调试。删除已打开端口时走统一关闭流程；相关路由和定时任务显示失效目标。

TCP 客户端列表按 PeerId 绑定选择；连接消失后显示“原客户端已断开，请重新选择”，新连接不会继承旧选择。所有端口的关闭和停止按钮在高负载期间始终可用。

## 4. 数据监视

RX 与 TX 使用不同颜色/方向标识；发送显示“已入队、写入中、本地完成、失败”，提示“本地完成不代表对端应用收到”。可按端口、客户端、方向筛选；筛选不改变实际收发或转发。

数据显示格式与发送区共用 `PayloadCodec` 同一套解析/渲染规则，可选 HEX、DEC、BASE64、UTF-8、GBK、ASCII、转义字节七种。渲染是容错的：非法 UTF-8/GBK 序列以替换符呈现，NUL/控制字节与 ASCII 之外的字节以 `\xNN` 转义呈现，绝不因数据内容报错；搜索同时匹配当前格式的渲染文本、UTF-8 文本与两种 HEX 写法。选择记录可查看元数据、复制已保留字节、再次填入发送区，发送前重新确认当前目标。

时间戳使用毫秒显示，可展开单调时差。流片段标记为“数据片段”，UDP 标记为“数据报”，避免让用户把 TCP readyRead 分块误认为协议帧。

- 暂停：冻结当前视图，后台继续通信；恢复时显示遗漏记录数。
- 清空：只清除显示历史；另设“重置统计”。
- 自动滚动：用户滚动查看旧数据时停止跟随，点击“跟随最新”恢复。
- 容量：始终提示截断/淘汰数量，大数据记录显示“预览前 N 字节，共 M 字节”。
- 完整记录：通过独立按钮开启，显示路径、已写入量和完整性状态。

## 5. A/B 桥接

桥接块竖排在 A、B 两行右侧，不维护规则集合、也不再是独立页签或独立行。它不设固定宽度和独立底色（`WA_StyledBackground` 关闭，QSS 的底色规则因此不再绘制），与端口选择区共用一张白色面板，宽度取方向下拉与按钮中较宽者的内容宽度。端点对固定为 A↔B，因此没有标题和成对摘要标签。结构上桥接块**镜像端点列的「行 / 分隔线 / 行」**：上下两半以相同 stretch 拉伸、中间延续同一条 `EndpointDivider` 分隔线，方向下拉与"建立桥接"按钮（带 ⇄ 图标）各自纵向填满所在半区——因此两列的行高、分隔线位置和控件顶边天然对齐（连接/监听按钮与桥接控件填满行高，不再因居中产生 1px 错位，测试断言映射到窗口后的顶边 y 相等）。方向即摘要，共三个选项：`A → B`、`B → A`、`A ↔ B`（默认双向），每个选项带各自的方形方向图标——文字箭头依赖字体回退（`↔` 不在雅黑字库内）会渲染发虚，图形不依赖字体；端点的完整派生名（`A · 串口` 等）与当前方向放进按钮的悬停提示。建立后方向锁定、按钮变为"停止桥接"；停止后才能调整方向。

按钮仅在两个端点的配置都通过完整性校验时可用。未满足时不写常驻提示行——禁用的按钮本身就是信号，原因放在按钮的悬停中；运行状态由状态栏的桥接字段呈现。桥接运行期间修改任一端点的类型或参数会立即停止桥接，必须重新建立——参数变了就不是原来那条链路。`--routes` 命令行入口不再切换页签，只把焦点移到这个常驻按钮。

串口、TCP 客户端、TCP 服务器和 UDP 都通过同一个端点配置页完成参数设置。TCP 客户端、TCP 服务器和 UDP 的 peer/目标细节属于端点自身，桥接页不再暴露来源过滤、客户端汇聚、分包或拥塞规则。需要调整连接方式时，回到 A 或 B 修改类型与参数即可。

桥接引擎按原始字节传递数据；流与 UDP 数据报的边界差异在端点状态或错误提示中说明，不在主页面增加协议规则。当前原型建立后标记为“已建立 · 预览”，真实通信接入后沿用“建立桥接 / 停止桥接”这一个动作入口，启动前检查两个端点配置有效且不能相同。

## 6. 自定义发送

单次发送是工作台的常驻单页面板，不再用页签承载：正文输入框固定约三行文本（行高取自等宽字体自身，不随发送区纵向伸展），格式、末尾贴在正文下方并与字节数、最终字节预览共用一行；格式列表与数据显示区共用 `PayloadCodec`（HEX/DEC/BASE64/UTF-8/GBK/ASCII/转义字节），文本类格式不再单设编码下拉框。目标选择不再单占一行，作为 A / B / AB 三个按钮放在动作行的发送按钮旁边，发送时目标与动作在同一处确认。整个发送区贴着内容高度，多余纵向空间让给数据显示区。非法 HEX/转义显示错误位置和原因，发送按钮不可用。切换文本/HEX 模式不偷偷转换或改写输入，必要时提供明确的“转换内容”动作。

目标用 A / B / AB 三选一的可勾选按钮，与数据显示区的端点开关同款形态与勾选样式，互斥按钮组保证任何时刻恰好一个目标，不留“都不选”的空状态。端点不足两个时 B／AB 置灰并自动回落到 A。发送目标不再暴露端点自身的 peer/UDP 地址：那是端点配置的一部分，`TCP 服务器` 的客户端选择属于后续里程碑；原先的“端口默认目标”下拉框已删除。

快捷命令分组（命令列表：启用、名称、目标、模式、内容、尾部、间隔、次数、结果，支持增删、复制、上下移动、单行发送、顺序循环、导入导出）暂时从发送区撤下，后续以右侧可展开面板的形式回归；撤下期间命令不会持久化，`存为命令` 入口一并移除，避免留下没有落点的按钮。

周期任务启动后展示目标快照、已完成次数、missedTicks 和停止按钮；断线自动停止，目标改变不自动续发。间隔为调度目标，UI 不显示硬实时保证。

## 7. 扩展页面归属

工作台常驻能力继续放在 `src/ui/panels`；需要独立状态、较大操作区域或可单独打开的功能放在 `src/ui/pages`。页面通过 `PageRegistry/PageHost` 创建和切换，`MainWindow` 不直接持有协议会话、文件任务或配置存储对象。

| 页面 | 目录 | 对应业务模块 | 交互形态 |
| --- | --- | --- | --- |
| 消息编辑/命令列表 | `ui/pages/messageeditor` | `sending` | 工作台页面或独立 Tab |
| 协议查看/字段解析 | `ui/pages/protocolinspector` | `protocols` | 工作台页面或数据详情页 |
| YMODEM 文件传输 | `ui/pages/transfer` | `protocols/ymodem`、`transfers` | 独立任务页面 |
| 应用设置 | `ui/settings` | `PreferencesStore` | 模态设置窗口 |
| 关于 | `ui/dialogs/about` | 应用版本元数据 | 模态对话框 |

设置页面只编辑值对象并提交变更：窗口、主题、语言和快捷键写入 `PreferencesStore`；端口、路由、协议绑定、消息模板和传输任务写入 `SessionStore`。页面不直接调用 `QSettings`、读写工作区文件或访问传输对象。

## 8. 交互验收

在 1280×720、1920×1080 及 100%/150%/200% 缩放下检查关键控件可见、布局无覆盖；端口参数长描述支持提示而非拉宽整个窗口。常用字段有 label 与 Tab 顺序，图标按钮有文字提示，错误和状态不能只靠颜色识别。

## 9. 参考调试工具的吸收与取舍

参考界面体现了几类对调试工作有直接价值的模式。easyDebug 吸收其交互意图，采用固定 A/B 双端点和 Qt Widgets 架构，不复制具体品牌、颜色或移动端布局。

### 9.1 连接控制

- 参考桌面工具把串口、波特率和打开动作放在高频操作区，降低首次连接成本。
- easyDebug 同样把类型、参数和打开动作放在同一行：A、B 各一行，端点状态和连接按钮就在该行右端，不需要先选中再到别处操作。
- 每个端点只有一套连接状态和一个动作入口。连接状态必须显示动作、文字状态、错误原因和必要的重试入口；桥接动作独立于端点动作，不与之混用。

### 9.2 实时监视工具栏

参考工具提供实时、暂停/降速、HEX 显示、清空、保存、筛选和折叠等高频操作。接收监视没有标题行，顶部只有一行设置栏，固定保留以下顺序：

1. 示例数据标记：仅在载入示例数据时显示"示例数据 · 不计入收发统计"；空态不再显示任何文案，由文本视图区的空态提示承担。
2. **显示 A** / **显示 B**：两个可勾选按钮直接放在选项栏里，快捷切换显示范围（默认都开；只勾一个看该端点，都勾看全部，都不勾不显示）。
3. 编码切换（HEX / 文本 · UTF-8）与搜索框（占满剩余宽度）。
4. "显示设置"按钮：显示 RX、显示 TX、时间戳列与暂停显示收进同一个菜单，均为可勾选项；顶栏不为它们各留一个控件。
5. 导出记录、"滚动到底"（可勾选按钮，向上翻阅时自动取消）与清空显示。
6. RX/TX 字节数、速率、队列积压、显示遗漏和记录状态摘要（底部一行）。

暂停只冻结视图，不停止通信；显示降速或精简模式只降低 GUI 更新频率，不改变转发和原始记录。统计摘要使用快照批量更新，不在每个数据包到达时刷新整行控件。

### 9.3 自定义发送与命令分组

参考桌面工具的发送表把启用、内容、HEX、延时、分包和单行发送放在一行，参考移动工具则用设备分组、全选、展开/折叠和拖动排序管理大量命令。easyDebug 采用两层结构：

- 工作台保留“单次发送”，用于快速选择目标、编码内容、尾部和最终字节预览。
- `MessageEditorPage` 管理命令分组、启用状态、顺序、延时、次数、分包策略、单行发送和导入导出；分组支持全选、展开/折叠，排序通过显式拖动或上移/下移完成。

命令内容与目标端点分离保存。端点断开、删除或重建时，命令仍保留但显示目标失效，不静默改绑到其他端点。

### 9.4 日志和数据详情

参考移动工具将时间、级别、摘要、长度、原始数据和复制动作组合成一条可扫描记录，并提供日志类型过滤。easyDebug 的监视区以控制台文本行展示（行号/时间/方向前缀 + 载荷），悬停与导出承载结构化元数据；"填入发送区"由 TX 消息交互提供。

设置页面按“日志类型”和“显示选项”分组，支持接收、发送、错误、警告、信息、时间戳、数据长度、UUID、HEX 同显和精简日志等开关。筛选只作用于显示，不改变统计、转发或文件记录。

### 9.5 文件传输与 YMODEM

参考工具将文件传输单独组织为发送/接收模式、目标端点、原始/协议分包、文件选择、分包大小、间隔、进度和取消动作。easyDebug 将其落到 `ui/pages/transfer`：

- 页面顶部选择发送或接收、目标端点和协议；YMODEM 会话状态由 `protocols/ymodem` 管理。
- 页面中部显示文件、分包参数、当前块、速率、重试、剩余时间和错误原因。
- 页面底部提供开始、暂停、取消和重试；关闭页面不能隐式取消任务，返回工作台时保留任务状态。

文件传输不能占用实时监视的显示队列，也不能在 GUI 线程读写文件；完整文件和协议日志分别进入有界文件任务与记录队列。

### 9.6 视觉和交互取舍

- 吸收参考工具的高信息密度、紧凑工具栏、分组标题、明确危险动作和可复制数据；不采用大面积装饰卡片或依赖颜色才能理解的状态。
- 桌面端默认保持浅色工作区，主题切换属于设置项；暗色主题需要复用同一字号、间距和状态语义，不能另起一套布局。
- 蓝色用于主操作和选中，绿色用于 RX/成功，红色用于断开/删除/错误，橙色用于警告；每种颜色同时配合文字或图标。
- 控件边界必须可见：输入框和按钮边框用 `#a9b5c9`，正文 `#182334`，辅助文字 `#5c6880`，工作区底色 `#e9edf4` 与白色面板形成区分。主操作（连接/监听/绑定、建立桥接、发送）是实心 `#1d4ed8` 配白字；禁用态用 `#b7c5e6` 底色保持可读，不靠淡化到近乎不可见来表达。表头、分隔线和滚动条同样使用可分辨的中性色，不使用低于 `#c8d1e0` 的边框。
- 移动端的底部抽屉、全屏设置和大尺寸触控按钮只作为窄窗口适配方案，不改变桌面端的端点条、监视、发送和桥接层次。
